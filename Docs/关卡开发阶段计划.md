## 二、关卡推进与跳转机制详解（代码视角）

### 2.1 谁来驱动流程

**`PrototypeFlowController`**（[Assets/PersonaCards/UI/PrototypeFlowController.cs](Assets/PersonaCards/UI/PrototypeFlowController.cs)）是整局流程的唯一编排者，持有：

- `_flow`：`PrototypeFlowStateMachine`——阶段状态机（纯逻辑，[PrototypeFlowStateMachine.cs](Assets/PersonaCards/UI/PrototypeFlowStateMachine.cs)）
- `_journeyDeck`：`JourneyDeckState`——跨战斗的永久牌库 + 金币
- `_personaLoadout`：`PersonaLoadoutState`——4 槽装备（可交换位置）
- `_behaviorTracker`：`RunBehaviorTracker`——局内行为指标（喂给局终报告和铸牌）
- `_saveStore`：`PrototypeSaveStore`——JSON 存档
- 路线数据经静态门面 `RunRoute`（[RunRoute.cs](Assets/PersonaCards/UI/RunRoute.cs)）读取：资产 `RunRoute.asset` 注入或回落内置白盒，**流程编排零硬编码场次**。

### 2.2 阶段枚举与状态转移表

`PrototypeFlowStage`（[PrototypeFlowStage.cs](Assets/PersonaCards/UI/PrototypeFlowStage.cs)）共 10 个阶段（P0-1B 追加 `PersonaGen` 中局铸牌）：

```
MainMenu → PersonaSetup ──按节点 kind 分派──> Battle / BossReveal / PersonaGen
Battle 胜利 → Reward →（hasShopAfter ? Shop : 下一节点）
Shop → 下一节点（按 kind 分派）      PersonaGen →（确认铸牌）→ 下一节点
Battle 失败 → FailureResult → MainMenu
最终战斗胜利 → RunReport → PersonaForge →（收藏界面）→ MainMenu
```

状态机实现（[PrototypeFlowStateMachine.cs](Assets/PersonaCards/UI/PrototypeFlowStateMachine.cs)），**节点索引驱动、无场次硬编码**：

| 方法 | 转移 | 说明 |
|---|---|---|
| `StartNewRun()` | MainMenu → PersonaSetup | 清回程标记 |
| `ConfirmPersonaSetup()` | PersonaSetup → 按节点 0 kind 分派（Battle / BossReveal / PersonaGen） | 回程标记存在时回 BossReveal（保留节点） |
| `CompleteBattle(won)` | 失败 → FailureResult；胜利且最终节点 → RunReport；否则 → Reward | — |
| `ContinueFromReward()` | Reward →（hasShopAfter ? Shop : 下一节点） | — |
| `ContinueFromShop()` | Shop → 下一节点 | — |
| `BeginBossBattle()` | BossReveal → Battle | — |
| `CompletePersonaGen()` | PersonaGen → 下一节点 | 中局铸牌确认后直接推进 |
| `AdvanceToNextStage()`（私有） | `NodeIndex += 1` → 按 kind 分派 | BossBattle → BossReveal / PersonaGen → PersonaGen / NormalBattle → Battle |
| `ContinueToForge()` | RunReport → PersonaForge | — |

所有转移用 `Move(expected, next)` 守卫（[PrototypeFlowStateMachine.cs](Assets/PersonaCards/UI/PrototypeFlowStateMachine.cs)），防止非法跳转；`Restore` 上界 = StageCount - 1。

### 2.3 战斗场次如何配置——配表驱动（xlsx 一键导入）

场次配置不再写死在代码里（P0-1/P0-1B 已完成），完整链路：

```
策划改 Docs/人格牌.xlsx「关卡流程」sheet
   → 菜单 Persona Cards/Import Run Route From Xlsx（[RunRouteImportCommand.cs](Assets/PersonaCards/UI/Editor/RunRouteImportCommand.cs)）
   → XlsxTableReader（[XlsxTableReader.cs](Assets/PersonaCards/Core/Xlsx/XlsxTableReader.cs)，纯 BCL 读取器）
   → RunRouteTableMapper（[RunRouteTableMapper.cs](Assets/PersonaCards/Data/RunRouteTableMapper.cs)，行级全量校验 + Boss 池按序分配）
   → 覆写 RunRoute.asset（CopySerialized 原地更新，场景引用不失效）
   → 运行时 RunRoute 门面（[RunRoute.cs](Assets/PersonaCards/UI/RunRoute.cs)）供状态机/控制器读取
```

当前路线（= 配表初值，13 个阶段）：10 场普通战斗（550/625/675/775/875/975/1050/1275/1475/1900，每关出牌 4/弃牌 3）+ 3 个人格牌生成节点（顺序 4/8/12，各生成 1 张）。非最终战斗结束后进商店（9 次）。导入失败时资产零改动；资产缺失/校验失败时门面回落同值白盒。表格契约（必填列/枚举值/缺省规则）见 [P0-1B.md](KF/P0-1B.md) 第四节。

关键设计（P0-1B）：

- 关卡类型单列枚举：`普通战斗` / `Boss战斗` / `人格牌生成`；旧写法 `战斗` 兼容导入并警告。
- Boss 难度池按出现序自动分配（第 1/2/3 个 → 初级/中级/高级，第 4+ → 高级 + 警告）。
- "是否商店"列缺省 = 是（最终关除外）+ 警告。
- 场次种子 = 局种子 `_runSeed` + 节点 + 1；中局铸牌种子 = `_runSeed` + 节点 + 1000（确定性且互不重叠，读档复现）。
- 进度文案 `旅程 x / 10` 只计战斗；生成节点确认铸牌后**直接推进**（不回主菜单）。

### 2.4 战斗内部状态机

`BattleStateMachine`（[BattleStateMachine.cs](Assets/PersonaCards/Battle/BattleStateMachine.cs)）——纯逻辑、可序列化快照：

- 常量：[BattleStateMachine.cs:15-18](Assets/PersonaCards/Battle/BattleStateMachine.cs#L15-L18)：手牌上限 8、选牌上限 5、出牌 4 次、弃牌 3 次。**出牌/弃牌限制已参数化（P0-1B 步骤 3）**：构造器接受 `playsLimit/discardsLimit`（默认 4/3，校验 >= 1），每关由配表"手牌限制/弃牌限制"列传入；快照自记 limit（旧档缺字段回落默认）。**剩余 const：选牌上限 5（Boss 规则"狭窄桌面"仍需参数化，P0-2 剩余项）与手牌上限 8（Boss 规则"节制命令（弃牌-1）/最后机会（出牌-1）"只动出牌/弃牌，已覆盖）。**
- 开局：[BattleStateMachine.cs:47-48](Assets/PersonaCards/Battle/BattleStateMachine.cs#L47-L48)：用 `XorShift32Rng(seed)` 洗牌 → 补满 8 张手牌。
- 出牌 `TryPlaySelected`（[BattleStateMachine.cs:137-163](Assets/PersonaCards/Battle/BattleStateMachine.cs#L137-L163)）：选牌按手牌顺序 → `ScoringPipeline.Score`（牌型 → 计分牌 → 人格效果 → Boss 效果 → 汇总）→ 移入已出区 → 次数-1 → 达标即 Won，否则补牌并检查失败。
- 失败判定（[BattleStateMachine.cs:220-227](Assets/PersonaCards/Battle/BattleStateMachine.cs#L220-L227)）：出牌次数耗尽或牌堆+手牌全空且未达标 → Lost。
- 效果装配（[BattleStateMachine.cs:207-212](Assets/PersonaCards/Battle/BattleStateMachine.cs#L207-L212)）：`CreateScoringEffects()` **每次出牌前**组装 人格牌效果 + Boss 效果——这是"人格封印/人格延迟"类 Boss 规则天然的挂载点（按手数动态过滤）。
- 快照恢复：`BattleStateSnapshot` + 第二个构造函数，用于存档续局（含选中牌、Boss 内部状态）。

### 2.5 结算管线（Boss 规则扩展的关键约束）

`ScoringPipeline`（[ScoringPipeline.cs:11-16](Assets/PersonaCards/Cards/Scoring/ScoringPipeline.cs#L11-L16)）只允许三种效果阶段：

```
HeldAndGlobal（持牌/全局） → Persona（人格牌，按槽位从左到右） → BossFinal（Boss 后置修正）
```

⚠️ **没有"牌面计分"阶段**。GDD 的"花色审查/花色沉默/花色试探"要屏蔽指定花色的牌面筹码，而牌面筹码在 `ResolveScoringCards`（[ScoringPipeline.cs:63-87](Assets/PersonaCards/Cards/Scoring/ScoringPipeline.cs#L63-L87)）里硬编码结算，不经过 effect 白名单。实现时需要**扩展 EffectPhases 白名单（加 ScoringCards 阶段）或给管线加钩子**，这是 Boss 规则里唯一的架构级改动。

已有钩子：`PersonaScoringEffect.Apply` 已支持 `_slot.IsDisabled`（[PersonaScoringEffect.cs:37-41](Assets/PersonaCards/Battle/Personas/PersonaScoringEffect.cs#L37-L41)），即"人格封印"只需在开战时把对应 `PersonaSlot.IsDisabled` 置 true，管线零改动。

### 2.6 存档与恢复链路

- 写入：`PrototypeSaveStore`（[PrototypeSaveStore.cs:14-30](Assets/PersonaCards/UI/PrototypeSaveStore.cs#L14-L30)）JSON 原子写（.tmp → .bak 备份 → 替换），损坏时备份 `.damaged-时间戳` 后开新档。
- 数据结构：`PrototypeSaveData` schema v3（[PrototypeSaveData.cs](Assets/PersonaCards/UI/PrototypeSaveData.cs)）：阶段、场次号（语义 = 节点索引）、金币、牌库、收藏、装备、行为指标、**战斗快照**（含 Boss 手数状态、本场出牌/弃牌限制）。
- 触发点：每次稳定状态变化（选牌/出牌/弃牌后、战斗结算、商店购买、离开商店等）自动 `SaveActiveRun()`；战斗中不保存表现锁定中的快照。
- 恢复：`ContinueSavedRun`（[PrototypeFlowController.cs:588-624](Assets/PersonaCards/UI/PrototypeFlowController.cs#L588-L624)）重建全部状态 + 战斗快照，回到战斗中时手牌/分数/选中牌/Boss 状态完整还原，同一 seed 保证续局洗牌一致。

### 2.7 当前流程时序（简化，13 阶段混合链）

```
StartNewRun ──> PersonaSetup ──(确认装备，按节点0 kind分派)──> 节点0 战斗(550)
   │ 胜利 → Reward（免费强化，P0-6 改金币结算）→ Shop ──(离开)──> 节点1 战斗(625) → …
   │ 节点3 PersonaGen：铸牌 3 候选 → 确认 → 入收藏装备 → 直接推进（不回主菜单）
   │ … → 节点12 最终战斗(1900)
   │                                          │ 任意战斗失败
   ▼                                          ▼
RunReport（行为报告）→ PersonaForge       FailureResult → 主菜单
   ▼
收藏 + 自动装备（空槽）→ 主菜单（收藏界面打开）
```

节点明细：战斗 ×10（550/625/675/775/875/975/1050/1275/1475/1900，每关出牌 4/弃牌 3，非最终关后接商店 ×9）+ 人格牌生成 ×3（顺序 4/8/12，各 1 张）；Boss 行当前表未配置，导入后按 `Boss战斗` 类型自动走揭示 → 开战并分配难度池（P0-3 落地规则内容）。

| 人格铸造 | ★★☆ 低 | 可跑通：3 次 D20 → 映照/偏转/裂变三候选（全部以主导牌型为条件），[PersonaForgeState.cs:9-22](Assets/PersonaCards/UI/PersonaForgeState.cs#L9-L22) | GDD 6.x：16 模板池、强度档位表、去重与保底、AI 推荐标记、二次确认；当前无去重、无收藏查重 |
| 存档 | ★★★★☆ 高 | 原子写/损坏备份/战斗快照（含出牌弃牌限制）/装备与收藏持久化，schema v3；场次号语义 = 节点索引；旧档落生成节点时自动转铸牌阶段（同种子复现） | 需 schema v4（Boss 池状态、商店刷新价、剩余出牌奖励结算标记等） |

**结论**：战斗内核（牌库/牌型/计分/人格）质量高、测试覆盖好，**瓶颈全部在"流程编排层"（UI 程序集的硬编码）和"内容层"（Boss 池、商店服务、经济）**。跑通完整流程不需要动战斗内核，只有 Boss 花色类规则需要给计分管线开一个阶段白名单口子。

## 四、开发计划（两日目标：跑通完整流程）

### 4.0 目标流程（当前配表初值，13 阶段）

```
装备确认
 → 战斗1 (550) → 奖励 → 商店1 → 战斗2 (625) → 奖励 → 商店2 → 战斗3 (675) → 奖励 → 商店3

 → 战斗4 (775) → 奖励 → 商店4 → 战斗5 (875) → 奖励 → 商店5 → 战斗6 (975) → 奖励 → 商店6
 → 人格牌生成2
 → 战斗7 (1050) → 奖励 → 商店7 → 战斗8 (1275) → 奖励 → 商店8 → 战斗9 (1475) → 奖励 → 商店9
 → 人格牌生成3
 → 战斗10 (1900) → 局终报告 → D20 三选一 → 收藏/装备 → 主菜单
```

路线已实现为配表驱动：策划在「关卡流程」sheet 改行/加行（含 `Boss战斗` 行自动走揭示并按出现序分配难度池）→ 菜单一键导入，代码零改动。经济（P0-6）：初始 6 金币；普通战胜利 +4、Boss 胜利 +7、剩余出牌每次 +1；商店 3 商品位、刷新递增（2 起，每次+1，上限 5）；删除下限 20 张。

### 4.1 需要拍板的决策点（建议方案附后，开工前确认）

1. **商店服务范围**：冻结决策（DesignDecisions#8）说首版只有"删除、重刻与强化"3 项，GDD 有 7 项。
   → **建议**：P0 做 5 项（删除 5 金币 / 重绘花色 3 / 重刻点数 4 / 筹码强化 4 / 倍率强化 5），复制牌面 7 与万能花色 6 放 P2（万能花色要动 `CardEnhancement` 枚举 + 牌型判断，风险最高）。

### 4.5 技术风险与注意事项

1. **计分管线白名单**（P0-4）：`EffectPhases` 是 `private static readonly` 白名单，加阶段要同步检查 `ScoringPhase` 枚举、`ValidateAndOrderEffects` 的校验逻辑与既有测试对阶段顺序的断言，改动要小步走。
2. **const → 参数**（P0-2）：`StartingPlays=4 / StartingDiscards=3` 已随 P0-1B 参数化（每关独立限制、快照含 limit、旧档兜底默认值）；剩余 `HandLimit=8 / SelectionLimit=5` 仍为 const，被多处引用（含 `JourneyDeckState.Delete` 的下限检查 [JourneyDeckState.cs:59](Assets/PersonaCards/UI/JourneyDeckState.cs#L59) 用的是 `HandLimit`——**P0-7 改删除下限 20 时不要再引用 HandLimit**，改独立常量）。
3. **存档兼容**：schema v3 存档读入校验在 [PrototypeSaveStore.cs:39](Assets/PersonaCards/UI/PrototypeSaveStore.cs#L39)（1..3），升 v4 时决定"迁移旧局"还是"旧局作废只留收藏/装备"，比赛场景建议保留人格收藏与装备、活动局作废（成本最低、风险最小）。
4. ~~**种子策略**~~ ✅ 已实现（P0-1/P0-1B）：新局开跑时生成一次性 runSeed（存入存档），战斗种子 = `runSeed + 节点序 + 1`，中局铸牌种子 = `runSeed + 节点序 + 1000u`；同存档可复现（续局骰值一致）、不同局不同序，两个种子空间不重叠。
5. ~~**已知小问题（ReturnToPersonaSetup 不重建牌库）**~~ ✅ 已修复（P0-1）：`ReturnToPersonaSetup` 语义改为"保留本局回程标记"，不再重建牌库；放弃重开走 `StartNewRun`，会完整重建 52 张牌库并重置金币。
6. **Boss 随机状态入快照**：随机禁用槽位、随机花色、临时强化卡 id、已用规则集合都要进 `SavedBattle`/`SavedBehavior` 或新字段，否则续局后 Boss 行为漂移（同 seed 恢复原则）。
7. **断网完整通关**是参赛验收硬指标（GDD 13.4），P0 阶段所有新增文本必须本地可回退，AI 相关全部 P1。
