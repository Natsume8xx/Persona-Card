# 关卡开发阶段计划

> 版本：V1.0　日期：2026-08-18　作者：程序（AI 结对整理）

## 二、关卡推进与跳转机制详解（代码视角）

### 2.1 谁来驱动流程

**`PrototypeFlowController`**（[Assets/PersonaCards/UI/PrototypeFlowController.cs](Assets/PersonaCards/UI/PrototypeFlowController.cs)）是整局流程的唯一编排者，持有：

- `_flow`：`PrototypeFlowStateMachine`——阶段状态机（纯逻辑，[PrototypeFlowStateMachine.cs](Assets/PersonaCards/UI/PrototypeFlowStateMachine.cs)）
- `_journeyDeck`：`JourneyDeckState`——跨战斗的永久牌库 + 金币
- `_personaLoadout`：`PersonaLoadoutState`——4 槽装备（可交换位置）
- `_behaviorTracker`：`RunBehaviorTracker`——局内行为指标（喂给局终报告和铸牌）
- `_saveStore`：`PrototypeSaveStore`——JSON 存档

### 2.2 阶段枚举与状态转移表

`PrototypeFlowStage`（[PrototypeFlowStage.cs:3-14](Assets/PersonaCards/UI/PrototypeFlowStage.cs#L3-L14)）共 9 个阶段：

```
MainMenu → PersonaSetup → Battle → Reward / Shop / BossReveal
                                          └→ Battle → RunReport → PersonaForge → (收藏界面) → MainMenu
Battle 失败 → FailureResult → MainMenu
```

状态机实现（[PrototypeFlowStateMachine.cs](Assets/PersonaCards/UI/PrototypeFlowStateMachine.cs)）：

| 方法 | 转移 | 硬编码点 |
|---|---|---|
| `StartNewRun()` | MainMenu → PersonaSetup | — |
| `ConfirmPersonaSetup()` | PersonaSetup → Battle | `BattleNumber = 1` |
| `ContinueFromReward()` | Reward → Battle | `BattleNumber = 2` |
| `ContinueFromShop()` | Shop → BossReveal | — |
| `BeginBossBattle()` | BossReveal → Battle | `BattleNumber = 3` |
| `CompleteBattle(won)` | Battle → 按 BattleNumber 分发 | `1→Reward, 2→Shop, 3→RunReport`，失败→FailureResult |
| `ContinueToForge()` | RunReport → PersonaForge | — |

所有转移用 `Move(expected, next)` 守卫（[PrototypeFlowStateMachine.cs:70-79](Assets/PersonaCards/UI/PrototypeFlowStateMachine.cs#L70-L79)），防止非法跳转。

### 2.3 战斗场次如何配置——全部硬编码

**这是本次改造的核心目标文件。** `StartCurrentBattle()`（[PrototypeFlowController.cs:385-393](Assets/PersonaCards/UI/PrototypeFlowController.cs#L385-L393)）：

```csharp
var target = _flow.BattleNumber switch { 1 => 260L, 2 => 330L, _ => 420L };   // 目标分硬编码
var seed = (uint)(20260810 + _flow.BattleNumber);                              // 每场种子固定
var bossEncounter = _flow.BattleNumber == 3 ? BossEncounterCatalog.CreateMirrorKeeper() : null;  // 只有第3场有Boss
battleController.BeginBattle(target, seed, _journeyDeck.CreateBattleDeck(), _personaLoadout.CreateLoadout(), bossEncounter);
battleProgressText.text = $"旅程 {_flow.BattleNumber} / 3";                    // 进度文案硬编码 /3
```

流程闭环现状（与 GDD 对比）：

| 当前 | GDD 2.6 要求 |
|---|---|
| 普通战 260 分 → 奖励（免费强化） → 普通战 330 分 → 商店 → Boss 揭示 → Boss 420 分 → 报告 → 铸牌 | 序幕 350 → 商店1 → Boss1 550 → 商店2 → 普通2 1000 → 商店3 → Boss2 1500 → 商店4 → 普通3 2800 → 商店5 → Boss3 4200 → 局终结算 |

### 2.4 战斗内部状态机

`BattleStateMachine`（[BattleStateMachine.cs](Assets/PersonaCards/Battle/BattleStateMachine.cs)）——纯逻辑、可序列化快照：

- 常量：[BattleStateMachine.cs:15-18](Assets/PersonaCards/Battle/BattleStateMachine.cs#L15-L18)：手牌上限 8、选牌上限 5、出牌 4 次、弃牌 3 次。**全部是 const，Boss 规则"节制命令（弃牌-1）/狭窄桌面（选牌上限4）/最后机会（出牌-1）"需要把它们变成可配置参数。**
- 开局：[BattleStateMachine.cs:47-48](Assets/PersonaCards/Battle/BattleStateMachine.cs#L47-L48)：用 `XorShift32Rng(seed)` 洗牌 → 补满 8 张手牌。
- 出牌 `TryPlaySelected`（[BattleStateMachine.cs:137-163](Assets/PersonaCards/Battle/BattleStateMachine.cs#L137-L163)）：选牌按手牌顺序 → `ScoringPipeline.Score`（牌型 → 计分牌 → 人格效果 → Boss 效果 → 汇总）→ 移入已出区 → 次数-1 → 达标即 Won，否则补牌并检查失败。
- 失败判定（[BattleStateMachine.cs:220-227](Assets/PersonaCards/Battle/BattleStateMachine.cs#L220-L227)）：出牌次数耗尽或牌堆+手牌全空且未达标 → Lost。
- 效果装配（[BattleStateMachine.cs:207-212](Assets/PersonaCards/Battle/BattleStateMachine.cs#L207-L212)）：`CreateScoringEffects()` **每次出牌前**组装 人格牌效果 + Boss 效果——这是"人格封印/人格延迟"类 Boss 规则天然的挂载点（按手数动态过滤）。
- 快照恢复：`BattleStateSnapshot` + 第二个构造函数，用于存档续局（含选中牌、Boss 内部状态）。

### 2.5 结算管线（Boss 规则扩展的关键约束）

`ScoringPipeline`（[ScoringPipeline.cs:11-16](Assets/PersonaCards/Cards/Scoring/ScoringPipeline.cs#L11-L16)）只允许三种效果阶段：

```
HeldAndGlobal（持牌/全局） → Persona（人格牌，按槽位从左到右） → BossFinal（Boss 后置修正）
```

⚠️ **没有"牌面计分"阶段**。GDD 的"花色审查/花色沉默/花色试探"要屏蔽指定花色的牌面筹码，而牌面筹码在 `ResolveScoringCards`（[ScoringPipeline.cs:63-87](Assets/PersonaCards/Cards/Scoring/ScoringPipeline.cs#L63-L87)）里硬编码结算，不经过 effect 白名单。实现时需要**扩展 EffectPhases 白名单（加 ScoringCards 阶段）或给管线加钩子**，这是 Boss 规则里唯一的架构级改动。

已有钩子：`PersonaScoringEffect.Apply` 已支持 `_slot.IsDisabled`（[PersonaScoringEffect.cs:37-41](Assets/PersonaCards/Battle/Personas/PersonaScoringEffect.cs#L37-L41)），即"人格封印"只需在开战时把对应 `PersonaSlot.IsDisabled` 置 true，管线零改动。

### 2.6 存档与恢复链路

- 写入：`PrototypeSaveStore`（[PrototypeSaveStore.cs:14-30](Assets/PersonaCards/UI/PrototypeSaveStore.cs#L14-L30)）JSON 原子写（.tmp → .bak 备份 → 替换），损坏时备份 `.damaged-时间戳` 后开新档。
- 数据结构：`PrototypeSaveData` schema v3（[PrototypeSaveData.cs:7-21](Assets/PersonaCards/UI/PrototypeSaveData.cs#L7-L21)）：阶段、场次号、金币、牌库、收藏、装备、行为指标、**战斗快照**（含 Boss 手数状态）。
- 触发点：每次稳定状态变化（选牌/出牌/弃牌后、战斗结算、商店购买、离开商店等）自动 `SaveActiveRun()`；战斗中不保存表现锁定中的快照。
- 恢复：`ContinueSavedRun`（[PrototypeFlowController.cs:588-624](Assets/PersonaCards/UI/PrototypeFlowController.cs#L588-L624)）重建全部状态 + 战斗快照，回到战斗中时手牌/分数/选中牌/Boss 状态完整还原，同一 seed 保证续局洗牌一致。

### 2.7 当前流程时序（简化）

```
StartNewRun ──> PersonaSetup ──(确认装备)──> Battle#1(260, 无Boss)
   │ 胜利                                          │ 失败
   ▼                                               ▼
OnBattleCompleted → CompleteBattle(true)          FailureResult → 主菜单
   ▼
Reward（选一张牌免费领"筹码+20"强化）──继续──> Battle#2(330, 无Boss)
   ▼
Shop（删除/改花色/倍率强化，统一2金币）──离开──> BossReveal（硬编码镜厅守门人文本）
   ▼
Battle#3(420, 镜厅守门人：重复审判×0.60 / 先手鼓励+30筹码)
   ▼
RunReport（行为报告）──> PersonaForge（3次D20 → 映照/偏转/裂变三选一）
   ▼
收藏 + 自动装备（空槽）→ 主菜单（收藏界面打开）
```

## 三、各类型关卡完成情况评估

| 模块 | 完成度 | 现状 | 与 GDD 的差距 |
|---|---|---|---|
| 普通战斗 | ★★★★☆ 高 | 牌库/牌型 12 种/计分管线/人格牌/预览/结算事件/牌库查看器/牌型参考齐全；有完整测试 | 目标分数非 GDD 数值；`BattleNumber>=3` 一律 420 分 |
| 战斗奖励 | ★★☆ 低 | 奖励 = 免费给选中牌 +20 筹码强化（`GrantRewardEnhancement`，[JourneyDeckState.cs:33-36](Assets/PersonaCards/UI/JourneyDeckState.cs#L33-L36)），无金币发放 | GDD：胜利发金币（普通 4 / Boss 7 + 剩余出牌每次 1），奖励界面应为金币结算 |
| 商店 | ★★☆ 低 | 3 项服务**统一 2 金币**（删除/改花色/倍率强化，[JourneyDeckState.cs:38-50](Assets/PersonaCards/UI/JourneyDeckState.cs#L38-L50)）；无刷新、无售罄、无 3 商品位随机；删除下限 8 张 | GDD 8.3：7 项服务分档定价（3~7）；3 商品位不重复；刷新递增（2→最高5）；删除下限 20；重刻点数、复制牌面、万能花色缺失；金币不足灰态+差额提示 |

| 局终报告 | ★★☆ 低 | 4 个简化指标（主导牌型/集中度/筛选倾向/得分效率），[RunBehaviorTracker.cs:46-56](Assets/PersonaCards/UI/RunBehaviorTracker.cs#L46-L56) | GDD 5.2：12 项行为指标；标签白名单；AI 解释层（P1，需本地回退） |
| 人格铸造 | ★★☆ 低 | 可跑通：3 次 D20 → 映照/偏转/裂变三候选（全部以主导牌型为条件），[PersonaForgeState.cs:9-22](Assets/PersonaCards/UI/PersonaForgeState.cs#L9-L22) | GDD 6.x：16 模板池、强度档位表、去重与保底、AI 推荐标记、二次确认；当前无去重、无收藏查重 |
| 存档 | ★★★★☆ 高 | 原子写/损坏备份/战斗快照/装备与收藏持久化，schema v3 | 扩展节点流程后需 schema v4（节点索引、Boss 池状态、商店刷新价等） |
| 失败流程 | ★★★☆ 中 | 失败 → FailureResult → 回主菜单，符合"失败即结束本局" | 失败局的行为数据有效性判断（≥3场或≥8次出牌才铸牌）未实现 |

**结论**：战斗内核（牌库/牌型/计分/人格）质量高、测试覆盖好，**瓶颈全部在"流程编排层"（UI 程序集的硬编码）和"内容层"（Boss 池、商店服务、经济）**。跑通完整流程不需要动战斗内核，只有 Boss 花色类规则需要给计分管线开一个阶段白名单口子。

## 四、开发计划（两日目标：跑通完整流程）

### 4.0 目标流程（GDD 2.6 单局结构）

```
装备确认
 → 普通战1 (350) → 商店1 → Boss战1 (550, 初级规则池) → 商店2
 → 普通战2 (1000) → 商店3 → Boss战2 (1500, 中级规则池) → 商店4
 → 普通战3 (2800) → 商店5 → Boss战3 (4200, 高级规则池)
 → 局终结算 → 行为报告 → D20 三选一 → 收藏/装备 → 主菜单
```

经济：初始 6 金币；普通战胜利 +4、Boss 胜利 +7、剩余出牌每次 +1；商店 3 商品位、刷新递增（2 起，每次+1，上限 5）；删除下限 20 张。

### 4.1 需要拍板的决策点（建议方案附后，开工前确认）

1. **商店服务范围**：冻结决策（DesignDecisions#8）说首版只有"删除、重刻与强化"3 项，GDD 有 7 项。
   → **建议**：P0 做 5 项（删除 5 金币 / 重绘花色 3 / 重刻点数 4 / 筹码强化 4 / 倍率强化 5），复制牌面 7 与万能花色 6 放 P2（万能花色要动 `CardEnhancement` 枚举 + 牌型判断，风险最高）。
2. **奖励界面**：现在是"免费领强化"，GDD 是纯金币结算。
   → **建议**：改为 GDD 金币结算，强化全部走商店付费（也符合冻结决策"不保留免费测试入口"的精神）。
3. **Boss 形态**：GDD 是"同一 AI 角色 × 3 阶段"，每阶段从对应难度规则池抽 1 条主规则。
   → **建议**：P0 先做 3 个 `BossEncounterDefinition`（可都用镜厅守门人形象，换阶段名/难度池/台词档），规则池按难度各 3 条全部实现。
4. **目标分**：直接用 GDD 白盒初值 350/550/1000/1500/2800/4200（GDD 注明是初值，后续再调）。
5. **局终报告/铸牌**：保持现有简化版跑通即可，GDD 的 12 指标、16 模板、去重属于"人格核心"里程碑，不进这两天范围（只保证流程能走到三选一并入收藏）。

### 4.5 技术风险与注意事项

1. **计分管线白名单**（P0-4）：`EffectPhases` 是 `private static readonly` 白名单，加阶段要同步检查 `ScoringPhase` 枚举、`ValidateAndOrderEffects` 的校验逻辑与既有测试对阶段顺序的断言，改动要小步走。
2. **const → 参数**（P0-2）：`HandLimit=8 / SelectionLimit=5 / StartingPlays=4 / StartingDiscards=3` 被多处引用（含 `JourneyDeckState.Delete` 的下限检查 [JourneyDeckState.cs:59](Assets/PersonaCards/UI/JourneyDeckState.cs#L59) 用的是 `HandLimit`——**P0-7 改删除下限 20 时不要再引用 HandLimit**，改独立常量）。
3. **存档兼容**：schema v3 存档读入校验在 [PrototypeSaveStore.cs:39](Assets/PersonaCards/UI/PrototypeSaveStore.cs#L39)（1..3），升 v4 时决定"迁移旧局"还是"旧局作废只留收藏/装备"，比赛场景建议保留人格收藏与装备、活动局作废（成本最低、风险最小）。
4. **种子策略**：当前 `seed = 20260810 + BattleNumber` 每局相同——可复现是优点，但局局同序会显得假。建议新局在开跑时生成一次性 runSeed（存入存档），场次种子由 runSeed 派生（`runSeed ^ battleNumber`），保证"同 runSeed 可复现、不同局不同序"。
5. **已知小问题**：`ReturnToPersonaSetup`（[PrototypeFlowController.cs:403-409](Assets/PersonaCards/UI/PrototypeFlowController.cs#L403-L409)）重启新局时没有重建 `_journeyDeck`，旧牌库会被带入新局；P0-1 重写流程编排时顺手修掉（新局必须重建 52 张牌库 + 重置金币）。
6. **Boss 随机状态入快照**：随机禁用槽位、随机花色、临时强化卡 id、已用规则集合都要进 `SavedBattle`/`SavedBehavior` 或新字段，否则续局后 Boss 行为漂移（同 seed 恢复原则）。
7. **断网完整通关**是参赛验收硬指标（GDD 13.4），P0 阶段所有新增文本必须本地可回退，AI 相关全部 P1。
