## 〇、拍板与依据

- 无代策划确认专项拍板条目（A 表备注：最低风险接入）。本任务自定规则如下，已在本文档内固化：
  1. **权威键 = 花色+点数组合**（4×13=52，缺一/重复 = 错误，防误删）；`卡牌_ID`（CARD_001~052）仅存值（美术绑定 ID），对照图片配置「绑定ID」列校验，不在集合 = **警告**容错（同 P0-1C card_id 模式，策划改 ID 只需同步图片配置）。
  2. `卡牌类型` 当前仅支持「手牌」、`参数类型` 当前仅支持「筹码」：其他值 = **错误**（防静默丢数据，将来扩类型时同步扩契约与枚举）。
  3. **PlayingCardInstance.Id 保持 `standard-{suit}-{rank}` 不变**：卡牌实例 ID 参与存档/MoveCards/唯一性校验，改动波及面大；CARD_xxx 作为配置条目的 cardId 字段（美术绑定用途，与牌型配置 cardId 同角色）。
  4. 判定/计分语义不动：牌面筹码仍按「点数」驱动（配表当前 52 行同点数四花色筹码相同）；门面按 (花色,点数) 查表，为将来逐卡差异化留好口子。

## 一、开发内容

### 1. CardConfigEntry + 新枚举（Cards，新）
- `CardConfigEntry` 纯数据 POCO（**放 Cards 而非 Core**：Suit/Rank 枚举在 Cards 不搬移；Cards 同样 noEngineReferences，无引擎依赖；Data 访问 Cards 类型由 asmdef 引用保证——实现时发现 Data 原本未引用 Cards（反而是 Cards 引用 Data），已通过删除 Cards 的冗余 Data 引用 + Data 补 Cards 引用解决，无循环依赖）：cardId/displayName/cardKind/suit/rank/paramType/paramValue(int)。构造器校验：cardId 允许空（同 P0-1C cardId）、名称非空、suit/rank/kind/paramType 枚举有效（Enum.IsDefined）、paramValue ≥ 0。
- `CardKind { Hand = 1 }`（卡牌类型，当前仅「手牌」）与 `CardParamType { Chips = 1 }`（参数类型，当前仅「筹码」）两个新枚举，预留扩展。
- `CreateFallbackList()`：白盒 52 条 = 配表当前初值（表序 CARD_001~052：黑桃→红桃→梅花→方块 × A、2~10、J、Q、K；筹码 A=11/J/Q/K=10/其余=点数）。**数值只写此处**（循环生成，不手写 52 行）：资产白盒工厂与门面白盒回落同源于此，交叉校验测试防漂移。

### 2. PlayingCardRules → 门面（Cards，改）
- 保留类名（任务要求），静态状态改可注入：
  - `Configure(IReadOnlyList<CardConfigEntry> entries)`：null/空 → 回落白盒；从白盒 52 张字典起步逐条覆盖；重复 (花色,点数) → 整体回落白盒（抛 ArgumentException → catch）；成功摘要 `"{52} 张卡（{n} 张来自配置，{52-n} 张回落白盒）"` 经 `LastConfiguredSummary` 由调用方打 `[Card]` 日志（本程序集无引擎引用）。
  - `GetFaceChipValue(Suit suit, Rank rank)`：签名从 (Rank) 改为 **(Suit, Rank)**（唯一调用点 PlayingCardInstance 同步改；grep 确认无测试直接调用）。查配置；枚举无效抛 ArgumentOutOfRangeException（沿用旧语义）。Configure 后 52 组合必然齐全（白盒起步），查表恒命中。
  - `GetCardId(Suit suit, Rank rank)`：返回 CARD_xxx 绑定 ID（美术接入用；白盒回落时 = 表序值）。
  - 白盒筹码公式 = 旧 `GetFaceChipValue` 逻辑（A=11/J/Q/K=10/其余=(int)rank）——**行为零差异的落点**。

### 3. PlayingCardInstance（Cards，改一行）
- `FaceChipValue => PlayingCardRules.GetFaceChipValue(Suit, Rank)`（签名跟随）。计分管线 [ScoringPipeline.cs:74](../../Assets/PersonaCards/Cards/Scoring/ScoringPipeline.cs#L74) 无感。

### 4. CardConfigAsset（Data，新）
- `[CreateAssetMenu(menuName = "PersonaCards/CardConfig", fileName = "CardConfig")]`，路径常量 `Assets/PersonaCards/Data/CardConfig.asset`。
- 条目类：cardId/displayName/cardKind/suit/rank/paramType/paramValue（全 int/枚举/字符串，**无 decimal 问题**）。
- `Validate(out string)`：条目非 null、cardId 非空且唯一、(花色,点数) 不重复、名称非空、枚举有效、paramValue ≥ 0。（52 张齐全校验不在此层——缺卡由门面白盒补齐，同 P0-1C 五条容错模式。）
- 白盒工厂 `CreateFallbackEntries()`：转换自 Cards 的 `CardConfigEntry.CreateFallbackList`（数值同源）。
- `BuildEntries()`：资产 → Cards 条目（调用前应先 Validate）。

### 5. CardConfigTableMapper + 契约（Data，新）
- `ImageSheetContract`（新，供卡牌/将来人格牌共用）：ImageSheetName「图片配置」、ColBindingId「绑定ID」。（HandTypeTableContract 已有同名常量不重构，P0-1C 已完结。）
- `CardConfigTableContract`：SheetName「卡牌配置」；列 卡牌_ID/卡牌名称/卡牌类型/花色/点数/参数类型/参数1。
- `CardConfigTableMapper.Map(rows, ICollection<string> imageBindingIds)`（ICollection 避 span Contains 歧义，沿用 P0-1C 教训）行级全量校验、错误全收集不 fail-fast：
  - `卡牌_ID` 空/重复 = 错误；不在图片配置绑定 ID 集合 = 警告容错。
  - `花色` 固定映射 黑桃→Spades/红桃→Hearts/梅花→Clubs/方块→Diamonds，未知 = 错误；`点数` 固定映射 A→Ace/2~10/J→Jack/Q→Queen/K→King，未知 = 错误。
  - `卡牌类型` ≠「手牌」= 错误；`参数类型` ≠「筹码」= 错误；`参数1` 非负整数（解析失败/负数 = 错误）；`卡牌名称` 空 = 错误。
  - **(花色,点数) 重复 = 错误**；**52 组合齐全检查**（缺任一 = 错误「请确认该行未被误删」）。
- 产物 `CardConfigEntry` 按卡牌_ID 升序排列；返回 `CardMappingResult { Succeeded, Entries, Errors, Warnings }`。

### 6. CardConfigImportCommand（UI/Editor，新）
- 菜单 `Persona Cards/导入卡牌配置数据`（validate 置灰 + 方法内 Play Mode 双守卫，复制 HandTypeImportCommand 骨架）。
- 读 `Docs/人格牌.xlsx` 两个 sheet：「卡牌配置」+「图片配置」（各自独立内存流，容忍 Excel 占用；图片 sheet 读失败仅降级跳过对照）。
- 成功 → 临时资产填条目 → Validate → `EditorUtility.CopySerialized` 覆写（保 GUID）或缺失时 CreateAsset → 选中 + 摘要日志，前缀 `[Card]`；失败 → 全部错误 LogError，资产零改动。
- 公开 `CreateOrReset()`（白盒工厂，供场景重建兜底，同 HandTypeImportCommand 模式）。

### 7. 运行时接线（UI / UI.Editor）
- `PrototypeFlowController` 追加 `[SerializeField] CardConfigAsset cardConfig`，`Awake` 里三态：null → 警告 + `PlayingCardRules.Configure(null)`；Validate 失败 → 警告 + 回落；通过 → `Configure(cardConfig.BuildEntries())` + 摘要日志（前缀 `[Card]`）；`Configure(...)` 追加末参数。

- 场景重建菜单 `Persona Cards/Rebuild Battle Prototype UI` 后生效（不重建则白盒运行，功能不坏）。

### 8. 不动
- `StandardDeckFactory.Create()` 与实例 ID 格式（存档/牌堆逻辑零波及）；`DeckState`/`HandEvaluator`/`ScoringPipeline` 判定与计分语义；Suit/Rank 枚举（留在 Cards，不搬移）；存档 schema。
