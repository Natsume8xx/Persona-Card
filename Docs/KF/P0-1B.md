## 一、开发内容

### 1.1 背景

策划新配表 `Docs/人格牌.xlsx`「关卡流程」sheet 定义了 13 行关卡配置（10 战斗 + 3 人格牌生成），与当前 6 战路线（P0-1）漂移。同时旧状态机硬编码"胜利→奖励→商店"链，无法表达"人格牌生成"这类非战斗节点。

用户已拍板的方案决策：

- **编辑器导入（方案 A）**：不做运行时读 xlsx；策划改表后点菜单 `Persona Cards/Import Run Route From Xlsx` 一键完成。
- **关卡类型单列枚举**：`普通战斗` / `Boss战斗` / `人格牌生成`。
- **Boss 难度池按出现序自动分配**：第 1/2/3 个 → 初级/中级/高级，第 4+ 个 → 高级 + 警告。
- **"是否商店"为策划新增列**：缺列时战斗关卡默认"是"（最终关除外）+ 警告。
- **人格牌生成节点 = 中局铸牌**：复用 PersonaForge 界面，确认后直接推进到下一节点（不入收藏界面、不回主菜单）。
- **每关独立出牌/弃牌限制**：表列"手牌限制/弃牌限制"。
- **进度文案"旅程 x / 10"**：只计战斗，生成节点不计入。
- xlsx 位置不变：项目根目录 `Docs/人格牌.xlsx`。

### 1.2 数据模型扩展（Data）

`Assets/PersonaCards/Data/RunRouteAsset.cs`：

- `RunNodeKind` 追加 `PersonaGen`（**枚举末尾追加**，旧序列化值 0/1 不变，旧资产兼容）。
- `RunBattleNode` 追加 `playsLimit`/`discardsLimit`（int，**0 = 默认 4/3**）、`genCount`（int）。保持类名与 `battleNodes` 字段名不变（避免 .asset 序列化迁移）；构造器加可选参数重载，旧调用不破。
- 新增单一工厂 `RunRouteAsset.CreateDefaultNodes()`：13 节点白盒（= 配表当前数值），`RunRoute` 门面兜底与"Regenerate Run Route Asset"菜单共用此工厂，消灭多份拷贝漂移。
- `Validate` 按 kind 重写：战斗类目标分 > 0、限制 >= 0；Boss 必须有池；PersonaGen genCount >= 1、hasShopAfter 必须 false、忽略分数/限制；**最终节点必须是战斗类且 hasShopAfter = false**（防运行时越界推进）；删除"只有末节点可不进商店"旧规则（中段不带商店现在合法）。

### 1.3 RunRoute 门面（UI）

`Assets/PersonaCards/UI/RunRoute.cs`：

- `StageCount`（= 节点数，新增）与 `BattleCount`（语义改为 = 战斗类节点数）并存；`ShopCount` 不变。
- 新增 `NextNodeKindOf(index)`、`BattleOrdinalOf(index)`（只计战斗，生成节点抛 InvalidOperationException）、`PlaysLimitOf/DiscardsLimitOf(index)`（0 → StartingPlays/StartingDiscards，生成节点抛异常）。
- `DefaultNodes` 改调 `CreateDefaultNodes()`；`Configure` 逻辑不变（校验失败回落白盒）。

### 1.4 战斗参数化（Battle，P0-2 核心前置）

- `BattleStateMachine` 构造器追加 `int playsLimit = StartingPlays, int discardsLimit = StartingDiscards`（校验 >= 1）；公开只读 `PlaysLimit/DiscardsLimit`；`BattleStateSnapshot` 增加 `playsLimit/discardsLimit`（可选，默认 const），恢复构造器校验改对**快照自身 limit**。
- `BattlePrototypeController.BeginBattle` 加同名参数透传；HUD 分母改读 `_battle.PlaysLimit/DiscardsLimit`。无参调试入口不动。

### 1.5 状态机混合链（UI）

- `PrototypeFlowStage` 追加 `PersonaGen`（枚举末尾）。
- 私有 `AdvanceToNextStage()`：NodeIndex += 1 → 按 kind 分派 BossBattle → BossReveal / PersonaGen → PersonaGen / NormalBattle → Battle。
- `ContinueFromReward`：hasShopAfter ? Shop : AdvanceToNextStage；`ContinueFromShop` → AdvanceToNextStage；新增 `CompletePersonaGen()`（PersonaGen → AdvanceToNextStage）；`ConfirmPersonaSetup` 新局路径按节点 0 kind 三分派。
- `Restore` 上界改 StageCount - 1。

### 1.6 流程控制器接线（UI）

- 三处推进逻辑（奖励继续/商店继续/中局铸牌确认）统一收敛到 `HandleStageEntry()`：Battle → StartCurrentBattle / PersonaGen → BeginMidRunForge / 其他 → SaveActiveRun。
- `StartCurrentBattle`：传 `PlaysLimitOf/DiscardsLimitOf`；进度文案 `旅程 {BattleOrdinalOf} / {BattleCount}`。
- 中局铸牌：`BeginMidRunForge()` 用派生种子（`_runSeed + node.Index + 1000u`，确定性且不与战斗种子重叠）重建 `PersonaForgeState`；`ConfirmForgeCandidate` 按阶段分支——PersonaGen 时入收藏 + 装备后 `CompletePersonaGen()` 直接推进（**不回主菜单、不打开收藏**），局终铸造原逻辑保留。
- 商店继续按钮**动态文案**（Render 进入商店时按 `NextNodeKindOf` 设置）：Boss → "离开商店 · 前往 Boss" / PersonaGen → "离开商店 · 前往铸牌" / Normal → "离开商店 · 继续旅程"。
- BossReveal 规则文本的出牌/弃牌限制改读节点配置（删除 TODO(P0-2)）。
- 存档：`ToSavedBattle` 增写 playsLimit/discardsLimit；`FromSavedBattle` 兜底 `> 0 ? x : StartingPlays`（**JsonUtility 缺字段是 0 不是 const**）；`ContinueSavedRun` 加旧档守卫——节点 kind 为 PersonaGen 时改 Restore 至 PersonaGen + 同种子重建 forgeState（骰值复现）。schemaVersion 保持 3（P0-8 再升 v4）。

### 1.7 xlsx 读取器（Core，纯 BCL）

`Assets/PersonaCards/Core/Xlsx/XlsxTableReader.cs`：

- `ReadTable(Stream xlsxStream, string sheetName)` → `List<Dictionary<string表头, string值>>`；不关闭调用方流。
- ZipArchive 读 workbook.xml + `xl/_rels/workbook.xml.rels` 定位 sheet → 文件（sheetId 不是文件名，必须走关系表；Target 兼容绝对/相对两种写法）；sharedStrings.xml；**用 local-name 匹配忽略命名空间差异**（兼容不同 Excel 生成器）。
- 归一化规则：表头行 = 首个非空行；"—"、空单元格、缺失单元格 → 空串；全空行跳过；数值按 invariant 字符串原样返回；重复表头/缺 sheet/坏文件抛 `XlsxTableReaderException`（消息带上下文）。
- 仅用 System.IO.Compression / System.Xml.Linq（.NET Standard 2.0 默认引用），**不破 noEngineReferences**，asmdef 零改动。

### 1.8 配表映射器（Data）

`Assets/PersonaCards/Data/RunRouteTableMapper.cs`：

- `RunRouteTableContract` 契约常量：SheetName「关卡流程」；列 关卡名称/顺序/关卡类型/分数参数/手牌限制/弃牌限制/AI节点/人格牌生成数量/是否商店；枚举值 普通战斗（"战斗"旧写法兼容 + 警告）/Boss战斗/人格牌生成；商店 是/否。
- `RunRouteTableMapper.Map(rows)` → `RunRouteMappingResult { Succeeded, Nodes, Errors, Warnings }`：
  - 按"顺序"列排序（重复/非正整数 = 错误，不连续 = 警告）。
  - **行级全量校验，任一行错则整体失败**（Errors 带行号 + 关卡名定位，不 fail-fast，策划一次看到全部问题）。
  - Boss 池按出现序分配（见 1.1）；"是否商店"缺列/空值默认"是"（最终关例外）+ 警告；非法值报错；生成节点忽略战斗字段（提示）、genCount > 1 强制 1 + 警告、显式"商店=是"报错；AI 节点与 kind 不一致警告；最终节点必须战斗类。

### 1.9 导入命令（UI.Editor）

`Assets/PersonaCards/UI/Editor/RunRouteImportCommand.cs`：

- `[MenuItem("Persona Cards/Import Run Route From Xlsx")]` + validate 函数（Play Mode 置灰）+ 方法内双重守卫。
- 路径 `项目根目录/Docs/人格牌.xlsx`；`FileStream(FileShare.ReadWrite)` 先读全字节再内存解析（容忍 Excel 打开占用的文件锁）。
- 失败语义：读取失败/映射失败/校验失败均 LogError 全部问题并 return，**资产零改动**；成功则临时资产 → `EditorUtility.CopySerialized` 覆写既有对象（保留场景引用）→ `existing.name = "RunRoute"`（**CopySerialized 不拷贝对象名**）→ SetDirty → SaveAssets → 选中资产。
- 完成日志输出摘要：阶段/战斗/Boss/生成节点/商店计数。日志前缀 `[RunRoute]`。
- `PersonaCards.UI.Editor.asmdef` references 增加 `PersonaCards.Core`。

### 1.10 场景构建器走查重写（UI.Editor）

## 四、表格契约（需转达策划）

「关卡流程」sheet 约定（已按当前表实测）：

- **必填列**：顺序（正整数、唯一、决定次序）、关卡类型、分数参数（战斗类）。
- **关卡类型枚举值**：`普通战斗` / `Boss战斗` / `人格牌生成`。⚠️ 当前表用旧写法 `战斗`，导入可兼容但会警告，请改为 `普通战斗`。
- **建议新增列**：`是否商店`（值 `是`/`否`）。当前表缺此列，战斗关卡默认结束后进商店（最终关除外）——请补充。
- 手牌限制/弃牌限制：空 = 默认 4/3（当前表填 4/3 也正确）。
- 人格牌生成数量：当前版本固定 1，填 > 1 会警告并强制 1。
- AI节点：仅生成节点有效；当前表战斗行也填了 1，会被忽略并警告，请清空战斗行的 AI 节点列。
- 生成节点的分数参数/手牌限制/弃牌限制会被忽略（当前表填了值，会警告），建议清空。
- 其余列（阶段_id/分数类型/奖励类型/奖励参数）当前不参与导入，改值无影响。

- **导入数据坏**：行级全量校验先于写入，资产零改动；可菜单回白盒（`Regenerate Run Route Asset`）；`git checkout -- Assets/PersonaCards/Data/RunRoute.asset`；最终防线 `RunRoute.Configure` 校验失败自动回落白盒。
