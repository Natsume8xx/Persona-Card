# P0-1C 牌型配置配表化 —— 可行性讨论稿（未实施）

> 日期：2026-08-20　状态：仅完成可行性讨论，**未进入开发**；待用户与策划确认第四节问题清单后立项　前置：P0-1B（本方案完全复用其 xlsx 导入三层结构）
> 结论速览：牌型配置 = "数据 + 算法"混合体。**数据层（名称/筹码/倍率/显示顺序/卡图 id）可配表化**，与关卡配置同构；**判定层（组合判定、计分牌选取、枚举集合、Priority）留在代码**，配表化是过度设计。

---

## 一、背景与可行性结论

策划配表 `Docs/人格牌.xlsx` 含「牌型配置」sheet（10 行），当前系统牌型数值写死在 `HandTypeCatalog.cs`（12 种旧占位值），两边已漂移。

### 1.1 结论：可以配表化，但拆两层看

| 层 | 内容 | 结论 |
|---|---|---|
| 数据层 | 名称、基础筹码、基础倍率、显示顺序、卡图 id | ✅ 配表化（复用 P0-1B 三层结构） |
| 判定层 | `HandEvaluator.DetermineHandType` 组合判定 if 链、`SelectScoringCardIds` 计分牌选取 switch、`HandType` 枚举集合、`Priority` | ❌ 留代码（算法非数据；配表化需自造 DSL/规则模板，GJ 项目过度设计） |

### 1.2 推荐形态：编辑器导入（同 P0-1B 方案 A）

新菜单 `Persona Cards/Import Hand Types From Xlsx` → 覆写 `HandTypeCatalog.asset`（保 GUID，`EditorUtility.CopySerialized` 模式）→ 运行时零依赖 xlsx、任一行校验失败则资产零改动、可回白盒。**不做运行时读 xlsx**（与 P0-1B 结论一致）。

## 二、现状与配表差异

| 维度 | 代码现状（写死） | 配表「牌型配置」 |
|---|---|---|
| 数量 | 12 种（含五条、同花五条） | 10 种（无五条/同花五条） |
| 基础筹码 | 5~100（旧占位值） | 48~100（策划新值：顺子 60 / 同花 65 / 葫芦 74 等） |
| 基础倍率 | int，1/2/2/3/4/4/4/7/8/8/8/8 | **含 2.5（两队）**，1~12（同花葫芦 12 最高） |
| 计分牌数 | 算法 switch（高牌取 1 张、对子取 2、两对取 4…） | 表有该列，但数值 1~10 与显示顺序完全一致，且同花=6 超过手牌上限 5，语义存疑 |
| 显示顺序 | 无（`Priority` = 枚举序，用于人格牌"最低牌型"条件判定，语义不同） | 显式 1~10 |
| card_id | 无 | `CARD_053`~`CARD_062` → 图片配置第 53~62 行确为 10 张牌型图，**但图片配置用小写 `card_053`** |

关键代码位置：`HandTypeCatalog.cs`（static 字典写死）、`HandTypeDefinition.cs`（BaseChips/BaseMultiplier 为 int，Priority = (int)HandType）、`HandEvaluator.cs:39-100`（判定 if 链）、`HandEvaluator.cs:102-133`（计分牌选取）、`PersonaScoringEffect.cs:72`（`evaluation.Priority >= (int)MinimumHandType`）。

## 四、待澄清/拍板问题清单（立项前需答复策划）

1. **五条/同花五条缺失**：代码能判定但表没配（52 张标准牌打不出五条，除非后续有"复制牌面"机制）。选项：a) 表补 2 行（代码不动，最稳）；b) 删代码判定（动枚举，风险大）。**建议 a**。
2. **"计分牌数"列语义**：数值 = 显示顺序 1~10，且同花=6 超过手牌上限 5，无法解释为参与计分牌数，疑似策划误填。**建议一期不导入该列**（忽略 + 警告），澄清后再接。
3. **2.5 小数倍率**：代码 int → decimal 可行（波及面可控）。确认设计允许小数倍率。
4. **card_id 大小写**：图片配置 `card_053`（小写）vs 牌型配置 `CARD_053`（大写）。导入时归一化小写，或反馈策划统一。
5. **"两队"笔误**：代码叫"两对"。以表为准则游戏内显示"两队"，建议反馈策划改表。
6. 顺带发现：「手牌配置」sheet 当前为空，可能关乎每手牌数/选牌上限，提醒策划补。

## 五、预估工作量与风险

- 工作量 ≈ 0.5~1 天：mapper ~150 行 + 命令 ~100 行（复制骨架）+ SO/门面改造 + decimal 波及 + 测试。
- 主要风险：decimal 波及面（倍率从 int 变 decimal 会传导到 `HandEvaluationResult` 与 HUD 文案格式化）；表与枚举不一致（缺五条等）需校验兜底（警告 + 白盒回落）。
