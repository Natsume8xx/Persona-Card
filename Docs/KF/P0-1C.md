## 一、开发内容

### 1. HandTypeDefinition：倍率 decimal 化 + 新字段（Cards/Hands）
- `BaseMultiplier` 类型 int → **decimal**（管线 `ScoringContext.SetMultiplier` 本就是 decimal，[ScoringPipeline.cs:60](../../Assets/PersonaCards/Cards/Scoring/ScoringPipeline.cs#L60) 无感）。
- 构造器追加两个可选参数：`int displayOrder = 0`（0 = 回落 `(int)handType`）、`string cardId = ""`。
- 校验：`baseMultiplier < 1m` 抛 ArgumentOutOfRangeException（沿用原语义）；displayOrder 允许 0。
- **红线不动**：`Priority` 仍 = `(int)HandType`（人格牌"最低牌型"判定用，与显示顺序是两个概念，绝不把显示顺序写回 Priority）。

### 2. HandTypeCatalog：static 字典 → 门面（Cards/Hands，同 RunRoute 模式）
- `Configure(IReadOnlyList<HandTypeEntry> entries)`：收 **Core 纯数据条目**。原因：Cards 程序集 noEngineReferences 不能引用 ScriptableObject 资产类型（CS0012），资产→条目的转换由 `HandTypeAsset.BuildEntries()`（Data 层）完成；null/空/重复牌型 → 回落白盒（本程序集无引擎引用不打日志，成功摘要经 `LastConfiguredSummary` 由调用方打 `[HandType]` 日志）。
- 白盒数值源 = `HandTypeEntry.CreateFallbackList()`（Core，唯一数值源）：**10 行为新表数值**（高牌 55/1、对子 48/2、两队 52/2.5、三条 57/3、顺子 60/4、同花 65/4、葫芦 74/5、四条 100/6、同花顺 95/10、同花葫芦 70/12；显示顺序 1~10；cardId HAND_01~10），**五条/同花五条保留占位**（100/8、显示顺序 11/12、cardId 空）。名称按表用「两队」。
- 条目缺某牌型（如五条/同花五条）→ 该牌型回落白盒条目，不报错（已拍板容错）。
- `Get`/`All` 语义不变；`All` 按 **DisplayOrder** 排序（UI 展示顺序 = 配表显示顺序）。

### 2.5. HandTypeEntry：Core 纯数据中转（Core，新）
- 无引擎依赖的纯数据条目（handType/displayName/baseChips/**baseMultiplier(decimal)**/displayOrder/cardId），构造时校验（名称非空、筹码 ≥0、倍率 ≥1、顺序 ≥0）。
- `CreateFallbackList()`：白盒 12 条 = 配表当前初值 + 五条/同花五条占位。**数值只写此处**：HandTypeAsset 白盒工厂（decimal→double）与 HandTypeCatalog 白盒回落（decimal 直达）同源于此，交叉校验测试防漂移。

### 3. HandTypeAsset：可序列化配置资产（Data，新）
- `[CreateAssetMenu(menuName = "PersonaCards/HandTypeCatalog", fileName = "HandTypeCatalog")]`，路径常量 `Assets/PersonaCards/Data/HandTypeCatalog.asset`。
- 条目类：`handType`（枚举）、`displayName`、`baseChips`(int)、**`baseMultiplier`(double，Unity 不序列化 decimal，运行时转 decimal)**、`displayOrder`、`cardId`。
- `Validate(out string)`：条目非 null、handType 不重复、displayName 非空、baseChips ≥ 0、baseMultiplier ≥ 1 且有限且不超 decimal 上界、显示顺序 ≥ 0。
- 白盒工厂 `CreateFallbackEntries()`：转换自 Core 工厂（数值同源，供导入命令创建初始资产与场景重建兜底）。
- `BuildEntries()`：资产 → Core 条目（double→decimal 转换在此完成）；调用前应先 Validate。

### 4. HandTypeTableMapper + 契约（Data，新）
- 契约 `HandTypeTableContract`：SheetName「牌型配置」；列 手牌_ID（权威键）/牌型名称/计分牌数/基础筹码/基础倍率/显示顺序/card_id；另含图片 sheet 常量（图片配置/绑定ID）。ID 值 HAND_01~HAND_10 固定映射核心牌型；**HAND_11/HAND_12 预留映射五条/同花五条**（策划补行即生效，现不在表 → 容错回落白盒）。
- 映射规则（行级全量校验，任一行错整体失败）：
  - `手牌_ID` → HandType 枚举固定映射（HAND_01=高牌 … HAND_10=同花葫芦）；未知 ID、重复 ID = **错误**；**核心 10 牌型缺行 = 错误**（防止策划误删行）；五条/同花五条缺行 = 容错（已拍板）。
  - `牌型名称` → DisplayName 原样导入；空 = 错误。
  - `基础筹码` 非负整数；`基础倍率` ≥1 的有限小数（double.TryParse invariant，解析后直接定型 decimal，产物为 Core 条目）；`显示顺序` 非负整数（空 = 0 回落枚举序）；解析失败 = 错误。
  - `计分牌数` 不导入；与显示顺序不一致 = 警告（A4）。
  - `card_id` 原样导入；对照图片配置「绑定ID」列全部非空值集合校验：空或不在集合中 = **警告**并容错（A2，策划会改）。
- 产物 `HandTypeEntry`（Core，decimal 倍率）按显示顺序排列；返回 `HandTypeMappingResult { Succeeded, Entries, Errors, Warnings }`。

### 5. HandTypeImportCommand（UI/Editor，新）
- 菜单 `Persona Cards/导入牌型配置数据`（validate 置灰 + 方法内 Play Mode 双守卫，复制 RunRouteImportCommand 骨架）。
- 读 `Docs/人格牌.xlsx` 两个 sheet：「牌型配置」+「图片配置」（各自独立内存流，容忍 Excel 占用）。
- 成功 → 临时资产填条目 → Validate → `EditorUtility.CopySerialized` 覆写（保 GUID）或缺失时 CreateAsset → 选中 + 摘要日志，前缀 `[HandType]`；失败 → 全部错误 LogError，资产零改动。
- 公开 `CreateOrReset()`（白盒工厂，供场景重建兜底，同 RunRouteAssetGenerator 模式）。

### 6. 运行时接线（UI / UI.Editor）
- `PrototypeFlowController` 追加 `[SerializeField] HandTypeAsset handTypes`，`Awake` 里：null → 警告 + `Configure(null)`；Validate 失败 → 警告 + `Configure(null)`；通过 → `Configure(handTypes.BuildEntries())` + 摘要日志（前缀 `[HandType]`）；`Configure(...)` 追加末参数。
- `BattlePrototypeSceneBuilder`：`EnsureHandTypeAsset()`（缺失时 CreateOrReset）+ 传入 flow.Configure；绑定校验列表追加 `"handTypes"`。
- 场景重建菜单 `Persona Cards/Rebuild Battle Prototype UI` 后生效（不重建则白盒运行，功能不坏）。

### 7. 波及修正
- `HandEvaluationResult.BaseMultiplier` 类型 int → decimal（一行）。
- `BattlePrototypeController.RefreshHandReference`：排序键 HandType → **DisplayOrder**；文案 `×{BaseMultiplier}` 自然显示 2.5。
- 旧测试期望值随新表更新（见第三节）。

### 8. 不动
`HandType` 枚举、`HandEvaluator` 判定 if 链与计分牌选取 switch、`Priority` 语义、asmdef、存档 schema。

## 五、风险与回退

- **Unity 不序列化 decimal**：资产存 double、运行时转 decimal（配表值 ≤2 位小数，转换无损）；配表解析即定型 decimal（Core 条目），只有资产层存储走 double；转换与校验集中在 HandTypeEntry（Core）/HandTypeAsset（Data）两处，交叉校验测试防数值漂移。
- **旧测试数值漂移**：新表数值变化是有意为之，逐条重算后更新断言（不允许顺手改逻辑断言）。
- **导入数据坏**：行级全量校验先于写入，资产零改动；`CreateOrReset` 回白盒；`git checkout -- Assets/PersonaCards/Data/HandTypeCatalog.asset`。
- **场景未重建**：handTypes 未绑定 → 警告 + 白盒运行，功能不坏；重建后自动挂接。
