## 〇、拍板与依据

- 范围（阶段计划已定）：
  1. **RULE_001（每关基础出牌次数 4）/RULE_002（每关基础弃牌次数 3）与战斗参数化归口**——默认值链从编译期 const 改为运行时门面（GlobalConfig），P0-1B 的每关限制回落值随之配表驱动。
  2. **其余 10 条只落数据**：门面提供通用读取 `TryGetInt/TryGetDecimal`，玩法接入等对应 P0（融合规则 B5、铸牌权重 B7、基础人格数量 C2 均在代策划确认中待策划回答）。
- 自定规则（本文档固化）：
  1. **只导入「全局配置」sheet**：4 列（规则_ID/规则名称/数值类型/配置数值）。
  2. **数值类型列「整数/小数」**：Mapper 按类型校验并保 string 原文（P0-1E 数值列模式）；整数规则配非整数字面量（如 4.5）= 错误；小数规则配整数字面量（如 3）= 允许。
  3. **RULE_001~012 齐全校验**（缺任一 = 错误「请确认该行未被误删」，防误删）；多出的规则_ID 允许（规则可扩展，不报错）。
  4. **门面放 UI 层**（GlobalConfig，与 RunRoute 同层）：Battle 层 `BattleStateMachine.StartingPlays/StartingDiscards` const 保留为**白盒兜底** + 构造器默认参数（C# 默认参数必须编译期常量）；运行时调用链一律经门面，白盒时门面回落 const 值 → 与现状零差异。
  5. **归口点两处**：`RunRoute.DefaultPlaysLimit/DefaultDiscardsLimit` const → static 属性转发门面（`PlaysLimitOf/DiscardsLimitOf` 已引用它们，自动归口，波及 Boss 揭示文本与 HUD 分母）；`PrototypeFlowController` 读档兜底 `BattleStateMachine.StartingPlays` → `GlobalConfig.StartingPlays`（读档时用当前全局配置而非编译期 const，语义正确）。
  6. **白盒回落 = 空配置**：Configure(null)/空资产/坏条目 → 空配置，StartingPlays/StartingDiscards 回落 4/3（现状零差异）；Configure 先全部校验再整体替换（防半状态，P0-1E 教训）。
  7. **槽位 RULE_003 只落数据**：`PersonaLoadout.SlotCount` 是 Battle 层 const，动态槽位波及 UI 布局与存档长度（等 P0 玩法任务）；门面可读但运行时不接。
  8. 非负校验（12 条规则均为非负量）在 Mapper、资产 Validate、门面 Configure 三层执行；权重 ≤1 不做校验（业务语义，等 B7 确认后由对应 P0 任务加）。

## 一、开发内容

### 1. GlobalConfigEntry + GlobalConfigAsset（Data，新）
- `GlobalConfigEntry` 顶层纯 C# 类（P0-1E 模式：资产层全 string 原文，noEngineReferences 边界无忧）：`ruleId`/`ruleName`/`valueType`（string 原文「整数」/「小数」）/`valueText`（string 原文，空=无）。
- `GlobalConfigAsset`：`[CreateAssetMenu(menuName = "PersonaCards/GlobalConfig", fileName = "GlobalConfig")]`，路径常量 `Assets/PersonaCards/Data/GlobalConfig.asset`，`entries` List<GlobalConfigEntry>。
- `Validate(out string)`：空条目 = 合法（白盒）；ruleId 非空、唯一、`RULE_\d{3}` 格式；名称非空；valueType ∈ 契约 {整数,小数}；valueText 非空、可 parse、非负；整数规则要求整数字面量。

### 2. GlobalConfigTableMapper + 契约（Data，新）
- `GlobalConfigTableContract`：SheetName「全局配置」；列 规则_ID/规则名称/数值类型/配置数值；`ValueTypes = { "整数", "小数" }`。
- `GlobalConfigTableMapper.Map(rows)` 行级全量校验、错误全收集（P0-1E 模式）：
  - ruleId 空/坏格式/重复 = 错误；RULE_001~012 齐全校验（缺 = 错误，多 = 允许）；名称空 = 错误。
  - 数值类型未知 = 错误；配置数值空/非数字/负值 = 错误；整数规则配非整数字面量 = 错误。
  - 错误文案 `第 {rowIndex + 2} 行「{ruleId}」`；entries 按 ruleId 升序。

### 3. GlobalConfig 门面（UI，新）
- `Configure(IReadOnlyList<GlobalConfigEntry> entries)`：null/空 → 白盒空配置（summary null）；逐条校验（格式/类型/数值/唯一/非负）任一失败 → 整体回落白盒；成功 → 整体替换 + `LastConfiguredSummary = "{n} 条全局配置已加载。"`。
- `StartingPlays`/`StartingDiscards`：TryGetInt("RULE_001"/"RULE_002") 命中则用之，否则回落 `BattleStateMachine.StartingPlays/StartingDiscards`（白盒零差异）。
- `TryGetInt(string ruleId, out int)`：条目存在且 valueType=「整数」且 invariant 解析非负；`TryGetDecimal` 同理（「小数」，decimal.Parse 精确保存）。
- 静态幂等缓存；Configure(null) 清空（测试 [TearDown] 防泄漏，P0-1E 模式）。

### 4. 归口改动（UI）
- `RunRoute.DefaultPlaysLimit/DefaultDiscardsLimit`：const → static 属性转发 `GlobalConfig.StartingPlays/StartingDiscards`（注释：单一来源 = 门面，Battle const 为白盒兜底）。
- `PrototypeFlowController` 读档兜底（ToSavedBattle/FromSavedBattle 段）：`> 0 ? x : BattleStateMachine.StartingPlays/Discards` → `GlobalConfig.StartingPlays/StartingDiscards`。
- `BattleStateMachine`/`BattlePrototypeController` 不动（const 白盒兜底 + 默认参数编译期约束；补充注释「运行时调用链经 GlobalConfig 门面」）。

### 5. UI.Editor 接线
- `GlobalConfigImportCommand`：菜单「Persona Cards/导入全局配置数据」+ validate 置灰 + Play Mode 双守卫；模式照抄 PersonaImportCommand（FileShare.ReadWrite 内存流读「全局配置」sheet、行级校验、失败错误全收集资产零改动、成功临时资产 Validate → CopySerialized 覆写保 GUID → 选中 + 日志 `[Global] 配表导入完成：{n} 条全局配置已写入 GlobalConfig.asset。`）；`CreateOrReset()` 空条目资产（白盒）。
- `PrototypeFlowController`：新增 `[SerializeField] private GlobalConfigAsset globalConfig` 字段（personaConfig 字段后）；Configure 签名末参 + 体末赋值；Awake 三态注入块（personaConfig 块后）：null → 白盒警告 `[Global]`；Validate 失败 → 白盒警告；成功 → Configure + 摘要日志。
- `BattlePrototypeSceneBuilder`：`EnsureGlobalConfigAsset()`（缺失时 CreateOrReset + `[Global] 场景重建时发现全局配置资产缺失，已创建空条目资产（白盒）。`）；Configure 调用追加；校验列表加 `"globalConfig"`。
