## 三线强化（P0-11）语义确认

> 三线强化系统已实装（人格牌 Lv0~4 / 花色 Lv1~4 / 牌型 Lv1~4 + 商店 3 个强化服务）。以下为实施中采用的临时口径，请策划拍板。

### 1. 强化数值叠加口径：加性叠加（花色逐张 / 牌型增量 / 人格单值升级）
- **花色强化**：对已打出的**计分牌**（本手牌型认定的计分牌）按花色聚合——每张计分黑桃额外 +5/10/15/20 筹码（Lv1~4）。同手多花色各自生效，与牌型底值、卡面值、人格效果全部**加性叠加**。
- **牌型强化**：本手命中牌型时，按强化表绝对底值 − 未强化底值的**增量**加筹码/加倍率（例：皇家同花顺 Lv1 = 110 筹码 ×13.2 倍率 → 增量 +10 筹码 +1.2 倍率；表内存绝对底值，程序算增量）。
- **人格牌强化**：按通用公式升级该人格牌效果单值——筹码型 +10/级、倍率型 +0.3/级、独立倍率型 +10%/级（详见条目 2）。原有人格效果触发条件/守卫逻辑（封印、延迟等）完全不变，只换数值。
- **待确认**：三线之间以及与人格牌原有效果，是否全部加性叠加？有无「乘算区」设计（如某线强化进独立乘区）？

### 2. 独立倍率型「+10%」两种读法——暂定 (a) 每级 +0.10 绝对量
人格牌强化规则表的独立倍率行写「+10%独立倍率」，存在两种读法：(a) 每级 +0.10 绝对量（Lv1 时 ×1.10，Lv2 时 ×1.20）；(b) 每级 ×1.10 复利（Lv2 时 ×1.21）。
**开发侧暂定 (a)**（与筹码型 +10/级、倍率型 +0.3/级的「每级固定增量」语义一致）。请确认；若为 (b)，只需改一处数值换算。

### 3. 人格牌强化表（PER_001~008 Lv0~4 绝对值）运行时零接线（仅告知）
该表需要「模板 → 运行时定义」转换（B7 词条映射）后才能接入，因此**当前未接线**；商店「强化人格」服务现在作用于装备槽里的教学 3 张卡（persona.initial.*），数值走条目 1 的通用公式（规则表驱动）。B7 完成 PER_* 装备流程后，强化目标自动变为正式人格牌，无需再改强化代码。
**无需确认**，仅告知。

### 4. 真实价格 8 + 3×当前等级（商品价 8 仅展示）
强化服务的商品表价格均为 8 金币，但实际扣款按**目标当前等级**查强化表价格列（8/11/14/17 = 8 + 3×当前等级）。商品位的「8」只是展示价，确认升级时按真实价格扣款，金币不足则拒绝且无副作用。
**待确认**：价格公式 8 + 3×等级是否符合预期？商品表价格列是否应同步改为 8/11/14/17 或「每级 3」的写法？

### 5. 服务池规则由程序临时合成（待策划补表）
强化服务 SHOP_SERVICE_006~008 当前不在任何刷新池（见「最新配表对比」条目 13）。开发侧已**临时合成 3 条服务池规则**（POOL_SERVICE_006~008，权重 20，对齐现有服务池）让服务上架可玩。**请策划补表**——补表后程序自动跳过合成（检测到同商品池规则即不重复添加），届时删除合成代码。

### 6. 强化等级入存档，schemaVersion 保持 3（仅告知）
三线强化等级已随存档读写（存 3 个列表：人格等级按 TemplateId、花色等级按花色、牌型等级按牌型）。旧档读入无字段 → 全 0 级，新版本读旧档/旧版本读新档均兼容，故 schemaVersion 不升。
**无需确认**，仅告知。

## 商店改造（P0-7）语义确认

> 商店系统已按策划案 10.6 实装（进入商店按 AI 分组与商品池生成商品位、限购、购买校验、货币不足不生效、扣款失败不生效）。以下为实施中发现的语义口径，均为临时口径，请策划拍板后统一。

### 1. 商店 AI 分组临时口径：按「已过生成节点数」映射
关卡流程表没有独立「AI节点」语义可供商店使用（战斗行 AI节点=0、生成行=1），程序按「进入商店前已过的生成节点数」映射：**0 个 → AI1、1 个 → AI2、≥2 个 → AI3**。
**待确认**：商店分组是否就是「第几个生成节点之后」的口径？若策划案中有别的分组依据（如按关卡序号、按章节），请说明。

### 2. 卡牌商品绑定方式：按商品名解析花色点数（无商品 id 列）
商品表没有「绑定卡牌 id」列，52 张卡牌商品的绑定按**商品名称解析**（「黑桃A」→ 黑桃+Ace，「方片10」→ 方块+10）。商品名若写错（如「鬼牌」「黑桃11」）该商品视为无效商品，不会上架（已有防御）。
**待确认**：正式方案是否加「绑定卡牌 id」列（如 CARD_001~052 或花色点数编码）？加列后程序改为按 id 绑定，无需按名解析。

### 3. 增加人格牌商品暂未上架（人格位显示「无货」）
「增加人格牌」效果需要 PersonaCardTemplate → PersonaCardDefinition 的转换（把词条/主属性/次级属性三表组装成运行时定义），这属于 B7「行为→词条映射」范畴，模板注释也标注「Template → Definition 转换届时另建」。**当前商店人格位恒显示「无货」**（AI1~AI3 组一致），B7 完成转换后商品池里 8 张人格牌自动恢复上架，无需再改商店代码。
**无需确认**，仅告知现状与后续计划。

### 4. 售罄态不随存档走——读档可绕过限购 1（P0-8 修复）
商品位按「局种子 + 节点序号」生成，读档重建必得同一批商品，但**售罄态不保存**：买了限购 1 的商品 → 存档 → 读档 → 该商品可再买一次。这是当前的已知漏洞，**P0-8 存档 schema v4 会把商品位（含售罄态）纳入快照**，届时修复。
**无需确认**，仅告知。

### 5. 商店内无「刷新」入口
进入商店时按商品刷新规则生成商品位，之后没有刷新按钮。商品刷新表里没有刷新消耗/次数规则，策划案 10.6 也未描述刷新机制。
**待确认**：是否需要商店内刷新（消耗金币？限几次？）？若需要请补充规则，程序加按钮即可。

### 6. 满牌库时买卡牌商品被拒绝（同 id 不可重复持有）
牌组按「同一张牌不可重复持有」规则运行：52 张全在牌组时购买任何「增加卡牌」商品都会提示「该牌已在牌组（先移除才能买回）」，**金币不扣、商品不售罄**。
**待确认**：正式规则是否允许重复持有同花色点数的牌？若允许，程序需把牌组唯一键从「花色+点数」改为「实例 id」；若不允许，满牌库时买卡必然失败是否符合预期（是否应直接置灰）？
