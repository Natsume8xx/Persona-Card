# 策划更新配表指南

> 适用对象：策划同学。读完本文，你只需要改一个 Excel 文件 + 一条消息，就能让游戏用上你的新数值。**不需要碰 Unity 工程。**

---

## 一、调整原理：一个可以反复跑的循环

调整数值就是三步的循环：

```
① 用 Excel 修改 Docs/人格牌.xlsx（改完保存）
        ↓
② 回到 Unity 编辑器，点上方菜单栏 Persona Cards → 导入关卡配表数据
        ↓
③ 点 Play 运行游戏，进新局验证效果
        ↓
不满意？回到 ① 继续改——改表 → 导入 → 试玩，无限循环
```

**为什么必须点导入**：xlsx 只是"编辑界面"，游戏真正读的是 Unity 里的一份配置资产（RunRoute.asset）。导入命令做的事 = 把 xlsx 内容校验后**原样同步**到这份资产。所以**每次改完表都要重新点导入**，游戏内容才会跟着变；只改 Excel 不点导入，游戏不会有任何变化。导入随时可重复执行，不需要重启 Unity。

**改错不会弄坏游戏**：导入前会逐行校验（顺序连续、类型合法、分数是数字等）。发现错误会拒绝导入并列出问题行，此时资产保持上一次的正确配置不变。

## 二、编辑器命令在哪里

导入命令位置固定：

> Unity 编辑器顶部菜单栏 → **Persona Cards** → **导入关卡配表数据**

- 菜单在 Play Mode（运行游戏）时置灰不可点，退出运行后才能点。
- 导入成功：Console 输出一条 `[RunRoute] 配表导入完成：13 个阶段 = …` 的日志。
- 导入失败：Console 输出 `[RunRoute]` 开头的**错误**日志（逐条列出问题行），此时资产保持原样零改动——把错误截图发给程序即可。

## 三、分支协作与工作流程

### 3.1 协作模式总览

三个分支，各司其职：

```
main     —— 主干：稳定版本。程序开发完成后合并到这里，并通知所有人
CH       —— 策划专用：你始终在这个分支上改配表、推送（此分支只有你推送，程序只读不写）
feature1 —— 程序的功能分支（举例名，实际以程序告知为准）：程序日常开发所在
```

日常节奏（完整一圈）：

```
① 你：在 CH 上改表 → 推送到远端 CH → 群里 @ 程序"配表已更新（CH 分支）"
② 程序：把 CH 分支的最新配表拉取合并进自己的功能分支 → 带着新配表继续开发
③ 程序功能开发完成：合并到 main → 通知所有人"main 已更新，可以拉取合并"
④ 你：收到通知后，把 main 的最新内容合并进 CH → 回到 ① 继续改表
```

你只需要关心 ① 和 ④；② ③ 是程序负责的。

### 3.2 策划侧完整命令（带注释）

以下命令全部在**项目根目录**的终端里执行，每步的 `#` 后面是说明：

```bash
# ============ 策划配表工作流（始终在 CH 分支上操作） ============

# ① 每次开始改表前，先同步远端，防止覆盖别人的新改动：
git checkout CH                  # 切到策划专用分支 CH
git pull origin CH               # 拉取 CH 分支的最新内容

# ② 如果群里收到"main 已更新"的通知，再加一步：把 main 合并进 CH
git pull origin main             # 拉取 main 最新内容并合并进当前的 CH 分支
#    如果这里出现 "CONFLICT"（冲突）提示：不要自己解决，
#    截图发群里找程序处理，程序会告诉你下一步怎么做

# ③ 用 Excel 修改 Docs/人格牌.xlsx，然后在 Unity 里点
#    Persona Cards → 导入关卡配表数据，进游戏试玩验证
#    （就是本文档第一节的"改表 → 导入 → 试玩"循环，调整到自己满意为止）

# ④ 确认满意后提交：
git status                       # 看一眼改动列表：除了 Docs/人格牌.xlsx，
                                 # 还会有 RunRoute.asset 等文件（点导入后生成的资产），这是正常的
git add -A                       # 全部提交即可，不用区分哪些文件该提交
git commit -m "配表：这里写本次改了什么，例如：第三关目标分 675→700"

# ⑤ 推送到远端 CH 分支：
git push origin CH               # 推送到远端的 CH 分支

# ⑥ 立刻在群里 @ 程序："配表已更新（CH 分支）"
#    程序看到后会拉取合并到自己的功能分支继续开发——这一步不能省
```

### 3.3 纪律与注意事项

- **不用区分提交什么**：点过导入后，`git status` 里会出现 `Docs/人格牌.xlsx` 和 `RunRoute.asset`（以后接入更多配表后还会出现更多资产文件）。**全部提交即可**——xlsx 是源头、资产是导入产物，程序拿到最新后都会重新执行导入兜底，两边内容必然一致。不要手动挑文件，避免漏提。
- **commit 信息统一前缀 `配表：`**，后面写清楚改了什么，方便程序快速看懂。
- **一次只改一件事**（比如只调数值、或只调顺序），出了问题好定位。
- **冲突不要自己解决**：任何 `CONFLICT` 提示都截图发群里找程序。
- 收到"main 已更新"通知后，先做 3.2 的第 ② 步合并，再开始改表。

## 四、「关卡流程」sheet 列说明（当前生效范围）

| 列 | 规则 |
|---|---|
| 关卡名称 | 任意文本，仅用于日志定位问题行 |
| 顺序 | 从 1 开始的连续整数，决定节点先后；重复或缺失会报错 |
| 关卡类型 | `普通战斗` / `Boss战斗` / `人格牌生成` 三选一。旧写法 `战斗` 也能导入但会警告，请统一改成 `普通战斗` |
| 分数参数 | 战斗类必填正整数（Boss 战也是填分数）；生成节点留空 |
| 手牌限制 / 弃牌限制 | 正整数；留空 = 默认 4 / 3；生成节点留空 |
| AI节点 | 生成节点填；战斗行请留空（目前填了会被忽略并警告） |
| 人格牌生成数量 | 生成节点填 `1`（当前固定三选一，>1 会被强制为 1 并警告）；战斗行留空 |
| 是否商店 | `是` / `否`；留空默认"是"（最后一场除外）。建议每行都显式填 |

其他注意：

- **Boss 战不需要自己选难度**：按出现顺序自动分配——第 1/2/3 场 Boss 分别为初级/中级/高级规则池，第 4 场起仍是高级并会警告（当前规则池内容未敲定，先跑占位规则）。
- 生成节点 = 中局铸牌（3 选 1），节点位置就是路线中铸牌发生的位置。

## 五、哪些表已接入 / 未接入

| sheet | 状态 |

## 六、遇到问题

- **导入报错**：截图 Unity Console 里 `[RunRoute]` 的错误日志，发给程序。
- **改错想回退**：还没提交时，在项目根目录执行 `git checkout -- Docs/人格牌.xlsx` 即可恢复成上次提交的版本，然后重新点一次导入（导入是幂等的，随时可重跑）。如果已经提交推送了，找程序处理。
- **不确定某列怎么填**：直接问程序，不要猜。
