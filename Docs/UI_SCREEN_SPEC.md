# 《人格牌》Unity MVP 界面详情规格

文档版本：1.0  
更新日期：2026-08-11  
目标平台：Windows PC  
基准分辨率：1920×1080（16:9）  
最低支持：1280×720

## 1. 文档目的

本文将 `E:\人格牌原型图参考` 中的 17 张灰阶原型整合为可供设计、程序、美术和测试反复查阅的界面规格。

原型图用于确认：

- 页面构成、信息层级和主要交互意图；
- 战斗界面三栏布局、卡牌区域和弹窗关系；
- 局终报告、人格铸造、三选一、收藏与装备的完整流程；
- 设置页、规则页和牌库查看器的基础结构。

原型图不用于确认：

- 牌型基础分、倍率、目标分和经济数值；
- 示例人格牌的正式名称、标签、触发条件和效果；
- 生命、伤害、经验、道具等当前核心规则中不存在的资源；
- “重试”“返回地图”“重新开始”等与已冻结流程冲突的按钮；
- 最终颜色、材质、字体、图标和插画品质。

## 2. 事实来源与冲突优先级

出现冲突时按以下顺序处理：

1. `PROJECT_HANDOFF.md` 中的正式核心设计与禁止修改项；
2. `Docs/DesignDecisions.md` 中已冻结的 Unity MVP 决策；
3. 本文定义的界面行为和信息架构；
4. 灰阶原型图中的布局参考；
5. 网页 Demo 的临时数值、按钮和占位文案。

任何 UI 都不能成为规则权威来源。牌型、分数、倍率、资源、Boss 效果、D20 结果和存档结果必须来自本地规则层或只读配置。

## 3. 已冻结的 UI 纠偏结论

| 原型内容 | 正式处理 |
|---|---|
| 失败页“重试” | 删除；失败即结束本局，不允许当前关卡重试。 |
| “返回地图” | MVP 没有可选路线地图；改为“继续旅程”或“返回主界面”，由当前流程决定。 |
| 结算页“重新开始” | 不在战斗弹窗直接重开；回主界面后可开始新局。 |
| 按键编辑/重绑定按钮 | 首个 MVP 不实现重绑定；可只读显示固定快捷键。 |
| 手柄设置 | 不进入首轮验收。 |
| 生命、伤害、防御、经验、随机道具 | 仅为原型占位；人格效果必须改写为合法的扑克、牌库、出牌、弃牌、分数、倍率或资源效果。 |
| 原型牌型数值 | 全部由正式 GDD 配置表生成，不硬编码原型数字。 |
| 普通战完整 Boss 栏 | 普通战显示轻量观察者/关卡规则区；只有 Boss 节点显示完整 Boss 区。 |
| AI 推荐等于最高骰点 | 禁止；AI 推荐依据行为画像匹配度，D20 只决定合法效果的强度档位。 |
| 获得人格牌后自动覆盖装备 | 禁止；满槽时必须由玩家明确选择替换对象。 |

## 4. 全局视觉与交互基线

### 4.1 视觉方向

- 最终视觉为黑曜石、旧金、暗红的神秘学牌局；灰阶原型只代表结构。
- 扑克牌必须优先保证传统可读性，牌角、点数和花色不得被装饰遮挡。
- 战斗背景使用低噪声中央牌桌，边缘承担装饰和 UI 框架。
- 重要动作使用旧金高亮；危险、失败和禁用使用暗红或低饱和灰红。
- 不直接复刻参考作品的图标、卡名、版式细节或品牌语言。

### 4.2 布局与缩放

- 所有页面以 1920×1080 为设计画布，支持等比缩放到 1280×720。
- 关键按钮、牌角数字、剩余次数和分数不得在 720p 下低于可读尺寸。
- 战斗界面按左侧人格区、中部牌局区、右侧观察者/Boss 与资源区组织。
- 弹窗宽度不超过安全区的 72%，高度不超过 84%；内容超出时只滚动内容区，标题和主操作固定。
- 超宽屏可扩展背景和边缘留白，不横向拉伸核心三栏。

### 4.3 弹窗规则

- 弹窗出现时背景整体变暗，禁止穿透点击。
- 战斗结算、Boss 揭示、目标选择和永久选择弹窗具有独占输入权。
- `Esc` 只能关闭允许撤回的查看型弹窗；规则提交、奖励确认和永久选择不能用 `Esc` 跳过。
- 危险或不可逆操作需要二次确认；关闭按钮必须有明确返回目标。

### 4.4 动画与输入

- 开场发牌、出牌入槽、计分、收牌、补牌期间锁定战斗命令。
- 减少动效模式允许缩短或立即完成表现，但不得改变状态机、随机数消耗或结算结果。
- 首次展示完整计分来源；之后可以加速，但必须允许查看日志。
- 所有禁用按钮需提供原因，例如“至少选择 1 张牌”“剩余弃牌次数为 0”。

### 4.5 通用数据状态

每个页面必须覆盖：

- 正常、空数据、加载中、禁用和错误状态；
- 超长名称、四位以上数值、倍率小数和本地化文本扩展；
- 存档写入失败后的保留与重试；
- 断网状态下的本地文案降级；
- 1280×720 下无文字截断和操作遮挡。

## 5. 页面与流程总览

```text
主界面
├─ 开始游戏 → 装备确认/新局初始化 → 战斗
├─ 继续游戏 → 恢复活动局快照
├─ 人格收藏/装备
├─ 图鉴/规则说明
├─ 设置
└─ 退出游戏

战斗
├─ Boss 节点 → 规则揭示 → 战斗
├─ 查看牌库/选择目标
├─ 查看牌型规则
├─ 胜利 → 奖励/商店 → 继续旅程或局终
└─ 失败 → 局终结算

局终有效
→ 局终人格报告
→ D20：映照 → 偏转 → 裂变
→ 三选一人格牌
→ 获得人格牌与装备确认
→ 收藏写入完成
```

## 7. 各页面详细规格

### UI-01 主界面

**目的**：作为新局、继续游戏、收藏、规则和设置的统一入口。

**布局**：

- 上中部：游戏标题《人格牌》和一句短副标题。
- 中部：纵向主菜单。
- 背景：低对比度牌面或神秘学构图，不影响按钮识别。

**正式按钮顺序**：

1. 开始游戏；
2. 继续游戏；
3. 人格收藏/装备；
4. 图鉴/规则说明；
5. 设置；
6. 退出游戏。

**行为**：

- 没有有效活动局时，“继续游戏”禁用并说明原因。
- 有活动局时点击“开始游戏”，提示是否放弃当前活动局；未确认不得覆盖存档。
- “退出游戏”在存在未完成写入时等待写入完成或显示错误处理。

### UI-02 战斗界面

**目的**：承载选牌、出牌、弃牌、牌型预览、逐阶段计分和战斗资源。

**固定三栏**：

#### 左栏：人格区

- 顶部显示本手基础分加成、倍率加成或独立乘区摘要。
- 下方固定 4 个装备槽，从上到下对应结算顺序 01→02→03→04。
- 每槽显示人格牌缩略图、名称、当前状态和本手触发反馈。
- 禁用人格牌保持原槽位并显示“本场禁用”原因，不挤压其他槽位。
- 点击可查看完整规则，但战斗开始后不能调整顺序。

#### 中栏：牌局区

- 上部：最多 5 张出牌/结算槽，用于展示已提交牌和逐阶段效果。
- 中部：牌型与计分摘要，包括当前牌型、基础筹码、基础倍率、独立乘区和预计/最终得分。
- 下部：最多 8 张扇形手牌；选中牌抬升并高亮，保留稳定排序。
- 最下：出牌、弃牌两个主按钮。

**选牌规则**：

- 只允许选择 1—5 张；再次点击取消。
- 第 6 张必须拒绝，并保持已有选择不变。
- 预览调用与正式结算相同的牌型判定服务，但预览不消耗随机数和资源。

#### 右栏：观察者/Boss 与资源区

- 普通战：轻量显示观察者头像、台词、关卡规则和目标信息。
- Boss 战：显示 Boss 名称、头像、台词、完整主规则与当前介入事件状态。
- 资源卡显示当前得分、目标分、进度条、当前金币和本场预计金币。
- 底部显示剩余出牌、剩余弃牌及其禁用原因。
- 设置按钮固定在右上安全区。

**计分表现**：

按“牌型初始化→计分牌/增强→留手/全局→人格 01—04→Boss 后置修正→汇总”依次播放；每一步显示来源、前值、变化和后值。

### UI-03 Boss 开战规则揭示

**目的**：在玩家首次出牌前完整揭示本场不可变规则。

**弹窗内容**：

- 标题“Boss 开战”；
- 左侧：Boss 头像和开场台词；
- 右上：本场主规则名称、图标、精确效果和作用域；
- 右下：本场介入事件名称、图标、精确效果和持续时间；
- 底部：查看规则、开始战斗。

**行为**：

- 只有点击“开始战斗”后才进入开场发牌。
- 主规则和介入事件来自本地配置；战斗中不得动态改变。
- “查看规则”打开 UI-05，不关闭当前揭示上下文。

### UI-04 牌库查看与目标选择

**目的**：查看当前战斗的牌区状态，并在商店或效果要求时选择合法目标。

**结构**：

- 顶部标签：当前牌库、已用牌、已弃牌。
- 摘要：总数、当前可选数、筛选条件。
- 卡牌网格：牌角、花色、增强标记和选择状态。
- 底部详情：选中牌的大牌面、ID/名称、增强标签与完整效果。
- 底部操作：确认选择、关闭。

**两种模式**：

- 查看模式：不可选目标，无确认按钮或按钮禁用。
- 目标选择模式：顶部显示目标条件，只允许选择白名单内卡牌。

**规则**：

- 卡牌必须显示真实所属区域；同场已用和已弃牌不能混回抽牌堆。
- 目标非法时显示具体原因；确认后返回调用页面。
- 选择行为不直接修改牌库，必须提交合法命令后才生效。

### UI-05 牌型规则/基础计分图鉴

**目的**：让玩家随时查阅正式牌型优先级和计分方式。

**内容**：

- 牌型序号、示例牌组、名称、基础筹码、基础倍率；
- A2345 和 10JQKA 边界说明；
- 页面底部显示正式计分公式和“查看详细规则”。

**正式约束**：

- 表格从 GDD 权威配置生成，禁止复制原型中的示例数字。
- 如果正式规则包含 12 种牌型，必须完整展示并可滚动。
- 表格变化不能通过 UI 代码修改规则数据。

### UI-06 战斗胜利结算

**目的**：说明胜利原因、最终得分和已获得奖励，并进入下一流程。

**建议采用的正式结构**：

- 胜利图标、标题和关卡/Boss 名称；
- 最终得分为最大视觉焦点；
- 可展开的牌型、基础筹码、倍率和来源摘要；
- 获得金币和剩余出牌奖励；
- 唯一主操作根据流程显示“领取奖励”或“继续旅程”。

**删除/改写原型项**：

- 不显示未定义的经验和随机道具；
- 不显示“重新开始”；
- 不显示“返回地图”；线性流程使用“继续旅程”。

**防重复**：奖励写入成功后才允许离开；恢复存档时不得重复领取。

### UI-07 战斗失败结算

**目的**：明确失败原因，结束本局并进入局终流程。

**内容**：

- 失败图标、标题、关卡/Boss 名称；
- 最终得分、目标分和差额；
- 本局是否达到有效行为门槛；
- 达到门槛：进入局终人格报告；
- 未达到门槛：显示简化总结并返回主界面。

**正式操作**：

- “查看局终报告”或“结束本局”；
- 不提供重试、当前关卡重开、返回地图或直接重新开始。

**奖励**：失败不发本场战斗金币；永久数据和局终候选按正式规则处理。

### UI-08 局终人格报告

**目的**：用可解释数据总结玩家本局玩法倾向，并进入人格铸造。

**结构**：

- 报告标题和本局人格概括名称；
- 2—4 个固定标签；
- 一段非诊断性的行为总结；
- 3—5 个核心指标条及百分比；
- 数据依据列表，每条可追溯至战斗或商店聚合事件；
- 查看详情、开始人格铸造。

**文案边界**：

- 只描述本局游戏行为，不判断现实人格、疾病、智力或心理状态。
- 本地规则先产生指标和标签；AI 只可润色名称、总结和解释。
- 断网时必须用本地模板完整显示。

### UI-09 D20 人格铸造

**目的**：依次生成映照、偏转、裂变三个不同规则方向的候选人格牌。

**顶部步骤条**：映照→偏转→裂变，当前步骤高亮，已完成步骤可查看但不可重投。

**中央区域**：

- D20 视觉与动画；
- 骰点数字和对应强度档位；
- 本次模式的候选结果卡：名称、标签、完整规则、次数/作用域；
- 下方保留已完成的三个结果槽。

**行为**：

- 每步只能提交一次正式投掷；投掷结果必须由确定性 RNG 产生并写入候选快照。
- D20 只决定合法效果的强度档位，不决定效果是否合法。
- 三个候选必须规则不同；重复时由本地去重和保底处理。
- 页面关闭、断线或写入失败后从候选快照恢复，不得重新掷骰刷结果。

**原型纠偏**：示例中的生命、伤害和防御文案全部替换为正式扑克系统效果。

### UI-10 三选一人格牌

**目的**：比较三个候选，查看推荐理由，并永久选择其中一张。

**布局**：

- 左侧/中部：三张等宽候选大卡；
- 推荐卡显示“推荐”标记，但不默认选中；
- 右侧：当前选中卡详情、完整规则和推荐理由；
- 底部：选择此人格、返回查看。

**行为**：

- 推荐依据为行为画像匹配度，不按骰点最高排序。
- 玩家可自由选择任一候选。
- 点击选择后弹出二次确认，明确“只保留一张，另外两张消失”。
- 确认写入失败时保留三个候选和玩家选择，不允许直接关闭。

### UI-11 获得人格牌与装备确认

> 本界面已按网页版截图重排落地（参考 `Docs/KF/UI/获得新的人格牌 的界面.png` 与界面描述文档），以下结构/行为为最新口径，替代旧三按钮草案。

**目的**：确认新人格牌已永久收藏，并决定是否立即装备。

**结构**（2:1 横向弹窗，遮罩拦截穿透、独占输入）：

- 顶部标题栏：左「获得新的人格牌」；右三列统计「本次获得 1张 / 当前持有 N张 / 当前装备 n/4」；
- 左面板「本次获得」：金框立绘位、卡牌名、类型标签、触发条件块、生效效果块；
- 右面板「当前装备」：2×2 四槽位网格，每槽显示槽号与槽内卡名（空槽显示「空槽」），选中态高亮；
- 底部通栏提示条：「{新卡名} → 槽位N，替换 {旧卡名}（旧牌保留）」，选中空槽时「{新卡名} → 槽位N，装备至空槽」；
- 右下角双按钮：「暂不替换，保留当前装备」/「替换 X 并继续」（选中空槽时「装备至 槽位N 并继续」）。

**行为**：

- 默认选中第一个空槽（有空槽时即推荐空槽）；满槽时默认选中槽位 01；玩家可点任一槽切换目标。
- 满槽替换不自动覆盖：玩家明确确认后才执行替换。
- 「暂不替换」：新牌只入收藏不装备，关闭弹窗继续流程，新卡仍永久保存。
- 「替换并继续」：替换执行后关闭弹窗继续流程；被替换旧牌仍在收藏（旧牌保留，收藏无上限）。
- 中局与局终铸造路径均触发弹窗；局终确认后直接回主菜单，不自动打开收藏页。
- 弹窗为永久选择，Esc 不能跳过；弹窗瞬态不入存档，读档回到铸牌屏可重新铸造选择。
- 存档落点沿用既有流程（弹窗确认后的阶段推进处）。

### UI-12 人格收藏/装备

**目的**：浏览永久收藏、查看详情、装备/卸下并调整 4 槽顺序。

**左侧收藏区**：

- 类型筛选、标签筛选和名称/效果搜索；
- 卡片网格与分页/滚动；
- 卡片显示主视觉、名称、标签和简短规则。

**右侧装备区**：

- 4 个固定槽位与 01→02→03→04 结算提示；
- 当前选中卡详情；
- 装备、卸下、交换顺序；
- 底部显示当前装备组合的规则摘要，不使用生命/伤害等未定义统计。

**行为**：

- 活动战斗开始后装备快照锁定；收藏页不能偷偷改变当前战斗快照。
- 所有永久装备修改需要确认并原子保存。
- MVP 收藏容量不设上限。

### UI-13 设置

**目的**：调整显示、音频、可访问性和固定操作提示。

**布局**：

- 左侧：画面、音频、操作、游戏、其他分类；
- 中部：当前分类设置项；
- 右侧：选中设置的说明和影响；
- 底部：恢复默认、取消、保存。

**MVP 必须项**：

- 主音量、BGM 音量、SFX 音量；
- 显示模式和 16:9 分辨率选择；
- 减少动效/快速结算；
- 固定快捷键的只读说明；
- 保存、取消、恢复默认。

**后续项**：亮度、UI 缩放、帧率上限和详细质量档位可在基础设置稳定后增加。

**本轮不实现**：按键重绑定、手柄专属设置和手柄验收。原型中的编辑铅笔/重绑图标不进入首个 MVP。

## 9. 数据绑定边界

| UI 数据 | 权威来源 |
|---|---|
| 手牌、抽牌堆、已用、已弃 | `DeckState`/战斗快照 |
| 牌型、计分牌、基础分、倍率 | 牌型判定与计分服务 |
| 人格触发与顺序 | 装备快照和 Persona 结算队列 |
| Boss 规则与介入事件 | 本地 Encounter 配置与战斗快照 |
| 出牌/弃牌剩余次数 | `BattleState` |
| 奖励与金币 | Run/Economy 结算结果 |
| 行为指标与证据 | Behavior 聚合结果 |
| D20 与三候选 | Forge 候选快照和确定性 RNG |
| 收藏与装备 | SaveData 永久数据 |
| AI 文案 | 受限 DTO；失败时使用本地模板 |

UI 只能发送命令、显示状态和订阅表现事件，不得直接修改这些权威数据。

## 10. 页面验收通用清单

- [ ] 1920×1080 和 1280×720 下无溢出、遮挡和不可点击控件。
- [ ] 鼠标与键盘均可完成主要流程；焦点顺序稳定。
- [ ] 动画期间重复点击不会重复提交命令或消耗资源。
- [ ] 减少动效与正常动效得到相同游戏状态。
- [ ] 弹窗不穿透输入，`Esc` 不跳过永久选择和存档确认。
- [ ] 规则、数值和候选来自权威服务，不从 UI 文本反向解析。
- [ ] 空数据、满槽、牌堆耗尽、超长名称和存档失败均有明确状态。
- [ ] 断网时仍可完成局终报告、D20、三选一、收藏和装备。
- [ ] 人格报告不产生现实心理诊断或敏感推断。
- [ ] Console 无新增 Error，关键页面具备 PlayMode 流程测试。
