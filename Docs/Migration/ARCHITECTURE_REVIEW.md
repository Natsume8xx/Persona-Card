# 架构审查与分阶段调整

日期：2026-09-09。结论：当前架构可作为 Windows 网页迁移版本继续迭代；规则复用合理，界面组织和长期平台能力需要调整。没有证据支持立即推倒重写。未测量性能，不能把代码问题描述成已经测得的帧率瓶颈。

## 已确认合理的部分

- NativeRules 用 ClearScript/V8 执行57个原网页模块，桥接层提供操作和快照；没有在C#重写第二套战斗数值，有利于当前行为一致。
- 音乐混合、短音效池、录音序列、设置事务已有独立类；表现不决定随机和战斗结果。
- NativePageTemplate/NativeAuthoredElement 通过键和基线恢复编辑覆盖，已有原生可编辑模板；普通构建不自动重新生成场景。
- 存档已使用临时文件、File.Replace和.bak备份；不是直接覆盖写入。捕获模式与正式存档分离。
- 已有回归和源导出哈希、目标同步前基线检查、备份及构建校验。

## 需要调整的部分

| 优先级 | 证据和问题 | 分阶段方案 |
| --- | --- | --- |
| P1 | NativeGameView各partial共享一个大对象，承担输入、JSON读取、页面生成、动画、音频和捕获测试 | 先提取只读页面展示模型；本轮新增NativeShopAffixPresentation。后续逐页Presenter绑定组件。拆文件本身不等于解耦 |
| P1 | Render销毁重建页面；成长选槽已有局部例外 | 先商店/图鉴选择与返回，再牌库；保留活动页面和局部绑定，验证手工覆盖、滚动、焦点、监听器不重复 |
| 已处理 | Upgrade原有PageId但无预制模板 | 已单独生成Upgrade.prefab、追加场景引用并检查运行时模板；没有全量BakeAll。渲染移入独立partial，仍需后续Presenter解耦 |
| P1 | 读取失败时只记录警告，未见自动加载.bak；lastStorage首次恢复后未初始化为实际读取内容 | 专门设计损坏恢复策略和注入式存档测试；不在界面修改中擅自重置/覆盖存档 |
| P2 | JObject字符串键散布页面，缺字段易运行时失败 | 从商店/成长逐步引入类型明确的只读模型；桥接保持兼容，不同时迁移全部页面 |
| P2 | 80次__flush固定循环，HTML模拟宿主与快照承担兼容 | 先记录耗时与事件队列上限，再改排空协议；保留顺序/随机/存档回归 |
| P2 | 测试捕获入口与EvaluateForTest保留在运行实现 | 单独验收入口/程序集或开发构建开关；保证发行构建不依赖测试脚本路径 |
| P2 | 固定设计画布和大量绝对坐标 | 先适配关键文本/滚动容器，再引入布局组件；保持网页信息层级 |
| 平台 | V8原生插件当前仅验证Windows x64 | 若目标转Android/iOS/WebGL需另做技术验证；没有自动跨平台保证 |

## 本轮实际改动

- 图鉴原画布局、单页模板更新；没有重建其他场景。
- 独立只读铸造说明转换，补空状态和限制原因，不复制解锁合法性逻辑。
- 建立页面清单与本报告，记录证据级别和未覆盖范围。

后续结构改动必须先选一个页面做完、测完，再推广。完整C#规则重写、远程AI和存档格式迁移不与界面结构重构捆绑。
